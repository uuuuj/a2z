# 도면 데이터 매핑 기준

도면에 찍히는 값이 **어디서 오는지**를 정리한 문서다. 현재 코드가 실제로 읽는 값과, 앞으로 정의해야 할 생산 데이터를 구분한다.

> **이 문서의 성격** — 완료/미완료를 추적하는 문서가 아니다. 진행 상태는 GitHub 이슈가 정본이고, 여기는 **"무엇을 어디서 읽는가"라는 데이터 계약**만 남긴다.
> 개발 현황 Excel의 `요구사항·UDA` 시트를 이관했다(2026-07-28).

---

## 1. 뷰 매핑

사용자 요구 방향과 코드의 `CameraDirection` 대응이다. 슬롯은 템플릿 `{View_n}` 번호다.
SDK enum의 부호는 **시선 방향이 아니라 카메라가 서는 축 방향**을 뜻한다.

| 도면 요소 | 카메라 위치 | 시선 | 화면 right / up | SDK 인자 | 템플릿 슬롯 |
|---|---|---|---|---|---|
| ISO | — | — | — | `ISO_PLUS` | `View_1` |
| 평면도 | +Z | −Z | +X / +Y | `Z_PLUS` | `View_2` |
| 측면도 | +X | −X | +Y / +Z | `X_PLUS` | `View_3` |
| 정면도 | −Y | +Y | +X / +Z | `Y_MINUS` | `View_4` |

**주의** — 요구 명칭이 "ISO3"이지만 SDK에는 그 이름이 없다. `CameraDirection.ISO_PLUS`가 요구하는 등각 방향과 일치하는 것으로 확정했다. 명칭 차이로 다른 뷰를 찾지 말 것.

도면 라벨의 부호 표기(`Looking −Z`, `Looking −X`, `Looking +Y`)는 담당자 확인 전까지 템플릿의 기존 `Looking Z/X/Y`를 유지한다.

## 2. BOM 컬럼별 데이터 출처

| BOM 컬럼 | 현재 출처·계산 | 권장 UDA / 규칙 | 비고 |
|---|---|---|---|
| 번호 | 앱이 Part/BOM 순번으로 생성 | UDA 불필요 | ISO 부재번호 풍선과 같은 번호를 쓴다 |
| ITEM | `SPREF` 앞 구간. 없음·빈값은 `unset` | `SPREF` | 후속 빈 데이터는 `-`로 표시 |
| MATERIAL | `MATREF` | `MATREF` | 선행 `/` 제거 |
| SIZE | `SPREF` 뒷부분 + `POSSTART`/`POSEND` 거리 | `SPREF` + `POSSTART`/`POSEND` | **좌표 숫자 순서를 가정**하고 있어 형식 검증이 필요 |
| Q'TY | **항상 1** | 수량 UDA 또는 동일부재 집계 규칙 | ⚠ 생산값 아님 |
| T/W | `GWEI` 숫자 파싱 | `GWEI` | 요약행은 합계 |
| MA | **데이터행 `L` / 요약행 `F`** | UDA·업무규칙 미정 | ⚠ 생산값 아님 |
| FA | **항상 `F`** | UDA·업무규칙 미정 | ⚠ 생산값 아님 |

### 템플릿 슬롯 번호

BOM 8컬럼 × 25행. **제작도·가공도 템플릿이 완전히 동일한 체계**를 쓴다.

| 행 범위 | No | ITEM | MATERIAL | SIZE | Q'TY | T/W | MA | FA |
|---|---|---|---|---|---|---|---|---|
| 1~20행 | 4~23 | 24~43 | 44~63 | 64~83 | 84~103 | 104~123 | 124~143 | 144~163 |
| 21~25행 | 201~205 | 206~210 | 211~215 | 216~220 | 221~225 | 226~230 | 231~235 | 236~240 |

첫 행은 요약행이다(No.=`00`, T/W는 STRU `GWEI`). 따라서 데이터행 정원은 24행.

## 3. 표제부 항목별 배선

| 항목 | 현재 값 / 배선 | 필요 데이터 | 비고 |
|---|---|---|---|
| Paint Code | `Input 166` ← 첫 비어 있지 않은 STRU `PNT` UDA | STRU 상위 UDA `PNT` | 4종 도면 실기 확인 완료 |
| PNOD / No Paint | 값 연결 없음 | UDA·판정 규칙 | Paint와 함께 정의해야 함 |
| Grinding / Welding | 값 연결 없음 | 부재/도면 단위 공법 데이터 | 업무 규칙이 우선 |
| Note | `Input 164`(내용)·`200`(라벨) 자리만 | 입력 UI · 저장 · 길이 정책 | 빈 Note 영역 테두리 제거 API는 해결됨 |
| Rev | `Input 170~199` 자리만 | 번호 · 일자 · 작성자 · 변경내용 | 데이터 모델·입력 UI 필요. 첫 기재행 괘선 API 대기 |
| Project Name | **`CEDAR FLNG` 고정** | 프로젝트 메타 / UDA | ⚠ 하드코딩 |
| Ship / Project No | **`SN2688` 고정** | 정식 필드와 데이터 소스 | ⚠ 하드코딩 |
| TAG NO | `Input 169` ← 조상 UDA `STRU` | 시트 종류별 기준노드 보강 | ⚠ 아래 주의 참조 |
| DP No | **`Test` 고정** | 정식 UDA / 메타 | ⚠ 하드코딩 |
| 회사 로고 | `Logo.png` → `{Image_3}` | 프로젝트별 교체 정책(선택) | 디자인 요소 |
| 고객/프로젝트 이미지 | `ClientTestImage.png` | 프로젝트별 파일 선택 | 디자인 요소 |

### ⚠ TAG NO — 시트 종류별 기준노드

`GetStruUdaValue(sheet.BaseMemberIndex)`로 조상 STRU까지 walk-up 하는데, `BaseMemberIndex`는 **시트 종류 식별자로 음수 센티넬을 쓴다**(제작도 −1 / 설치도 −2 / 가공도 −3). 함수 진입부의 `if (currentIdx < 0) break;`에 걸려 **조립도(실제 노드 인덱스)만 값이 채워진다.**

가공도는 별도 경로(`BuildMfgPageData`)라 `Input 169` 배선 자체가 없다. 자세한 내용과 조치는 GitHub 이슈를 볼 것.

### 표제부 슬롯 요약

| 슬롯 | 항목 | 슬롯 | 항목 |
|---|---|---|---|
| 1 | 프로젝트명 | 166 | PAINT CODE |
| 2 | 선박번호 | 168 | DP No |
| 3 | 도면종류 | 169 | TAG NO |
| 164 | Note 내용 | 170~199 | REV 표 |
| 200 | Note 라벨 | 241~245 | 부재명 (가공도 전용) |

`1~240`은 제작도·가공도 템플릿이 **동일한 의미**로 쓴다. 가공도 전용 확장은 **241번 이후**에만 추가한다.

## 4. 형상·출력 처리 기준

| 항목 | 현재 방식 | 필요 보강 |
|---|---|---|
| 기울어진 부재 참조축 정렬 | `ORIENTATION` UDA + ReferenceAxis 정렬 | 참조축 정렬은 완료. **치수 문자 각도만** 별도 API 대기 |
| 대각 치수 | 수평·수직 위치 치수만 유지 | **적용 제외 확정** — 생산 기준상 대각 선형 치수를 쓰지 않는다 |
| ISO 미리보기 상태 정리 | 진입 시 Measure·ShapeDrawing·3D Review Note 정리 | 없음. PDF 풍선 유지는 실기 확인됨 |
| 2D 출력 후 임시 치수 정리 | 출력 종료 `finally`에서 3D 임시 객체 정리 | 없음. 연속 출력 이월 없음 실기 확인 |
| 작은 치수선 길이 제어 | 외부 텍스트 배치 시 SDK가 치수선을 자동 연장 | 치수선·leader 길이 제어 API 요청 필요 |

## 5. 현업 확정이 필요한 항목

위 표에서 `필요 데이터`가 미정인 것만 모았다. **기술 난이도 문제가 아니라 데이터 출처·표기 규칙을 정해야 착수 가능한** 항목이다.

| 항목 | 물어야 할 것 |
|---|---|
| BOM Q'TY | 수량 UDA가 있는가, 없으면 동일부재 집계 규칙은? |
| BOM MA | 어느 UDA에서 읽는가 / 값 체계는? |
| BOM FA | 어느 UDA에서 읽는가 / 값 체계는? |
| PNOD / No Paint | 판정 규칙과 표기 방식 |
| Note | 입력 방식(앱 UI vs UDA), 긴 텍스트 처리 정책 |
| Rev | 이력 관리 범위 — 앱에서 관리하는가, 외부에서 받는가 |
| DP No | 정식 UDA 키 |
| Project Name · Ship No | 데이터 소스 (프로젝트 메타 or UDA) |
| TAG NO | 상세설계 STRU 이름 vs 생산설계 모델 이름 |
| 가공도 앵글 촬영 방향 | 기준면 · 열린 방향 · 미러 규칙 |
