# 가공도 보조선 길이 제작도 통일 (Step Mfg-ExtLine)

> **후속 변경 (2026-06-23, 관련: T-066)**: 식(공용 헬퍼 `ComputeCanvasAbsoluteOffsets`)은 통일 유지하되 **값은 도면별로 분기**. 가공도 보조선 오프셋을 종이 기준 **1단 2·전체 4mm**로 축소(제작도는 5/10 유지) — 사용자 사양 "가공도만, 많이". 헬퍼에 `canvasBase/canvasLvl` 인자(기본 5/5) 추가, 가공도 두 호출(`BuildMfgSceneCore`·EA 두번째 뷰)이 `MfgCanvasBaseOff`/`MfgCanvasLvlSp`(2/2) 전달. 통일의 핵심(종이 절대 길이 = 부재 무관 일정)은 그대로, 길이 값만 가공도가 작아짐.

## 1. 배경 / 문제

사용자 보고: **제작도는 모델 크기가 달라도 보조선 화면 길이가 일정한데, 가공도는 부재마다 제각각이고 세로 전체 길이 치수가 잘 안 나온다.**

- **제작도** (`ShowAllDimensions`, `Form1.Dimensions.cs:505~513`): 보조선 = 캔버스 절대 mm(1단 5 / 2단 10) ÷ 추정배율 → 모델좌표 offset. RescaleObject 후 화면 항상 5/10mm.
- **가공도** (`BuildMfgSceneCore`, `Form1.MfgDrawing.cs:753~757`): 보조선 = 모델좌표 고정값(50/100/250~300) × offFactor(100mm 경계 0.5/1.0). 배율 역산 없음 → 화면 길이가 부재 fit 배율에 비례 변동.

## 2. 현재 구조 — 무엇이 이미 공유되고, 무엇만 갈라졌나

| 요소 | 함수 | 공유 여부 |
|---|---|---|
| 보조선 **그리기** | `DrawDimension(...)` `Dimensions.cs:1080` (offset = 4번째 인자) | ✅ 이미 공유 |
| **offset 길이 계산식** | 제작도 `Dimensions.cs:509~513` vs 가공도 `MfgDrawing.cs:753~757` | ❌ 여기만 갈라짐 |
| 칸 맞춤 배율 | 제작도=추정(`EstimateFitScaleForViewArea`) / 가공도=실측(`fitRatio` `MfgDrawing.cs:315`) | ⚠️ **방식 자체가 다름** (Codex 차단 1) |

> **Codex 정정**: "offset 식만 갈라졌다"는 과장. fit 방식(추정 vs 실측), 모델이동(제작도만 `Dimensions.cs:525~604`), 풍선 정책(`MfgDrawing.cs:866~890`)도 다름. 보조선 길이만 통일하고 나머지는 건드리지 않는 게 핵심.

## 3. 목표 / 방식

> 보조선 길이 **정책**(화면 절대 5/10mm)을 공용 헬퍼로 단일화. 단 가공도는 **실측 배율**로 그 정책을 적용.

- 공용 헬퍼 `ComputeCanvasAbsoluteOffsets(scale)` — 제작도·가공도 공유. **scale 출처만 다름** (제작도=추정, 가공도=실측 newScale).
- `DrawDimension` 재사용.

## 4. 핵심 설계

### 4.1 공용 헬퍼 (좁게 — Codex 보강 3)
```csharp
private void ComputeCanvasAbsoluteOffsets(
    float canvasScale, out float baseOffset, out float levelSpacing, out float canvasMaxOff)
{
    const float canvasBase = 5f, canvasLvl = 5f;
    canvasMaxOff = canvasBase + canvasLvl;
    baseOffset   = canvasBase / canvasScale;
    levelSpacing = canvasLvl  / canvasScale;
}
```
- **스칼라 offset 결과만 반환.** 모델이동(`_lastModelShiftCanvasX/Y`)·레벨 그룹핑은 **추출 안 함** — 각 호출자에 남김.
- 제작도 `Dimensions.cs:509~513`을 이 호출로 교체 (동작 100% 보존).

### 4.2 1차 범위 — 본진 한 경로만 (Codex 차단 4)
가공도 보조선 생성 경로:
| 경로 | 위치 | fit 방식 | 1차 처리 |
|---|---|---|---|
| `RenderMfgRowToViewArea` | `MfgDrawing.cs:251~`, 호출 `:273` | `fitRatio` 실측 (예측 가능) | ✅ **1차 본진** |
| `ExecuteMfgDrawing` (3D 미리보기) | 호출 `:1168` | 3D, 칸 fit 없음 | ⏸️ 기존 유지 |
| `:1693` 경로 (`:1589`에서 호출, 2D) | `FitObjectToGridCellAspect`(`:1723`) + 30% target(`:1743`) + 20mm 하한(`:1754`) | **예측 불가** | ⛔ **1차 명시적 제외** |

> `:1693`은 어떤 추정·실측으로도 30%+20mm-하한 fit 결과를 보조선에 일관 반영하기 어렵다. 1차는 본진만. 이 경로 통일은 별도 작업으로 분리(범위 외).

### 4.3 가공도 offset 교체 (`MfgDrawing.cs:742~789`)
- `mfgChainOff1 = baseOffset`, `mfgChainOff2 = baseOffset + levelSpacing`, `mfgTotalOff = baseOffset + levelSpacing*maxLevel` (제작도 레벨 구조와 1:1)
- `offFactor`·고정값(50/100/250) 제거.

### 4.4 ⭐ 배율 = 실측 newScale (Codex 차단 1 — 방식 전환)
v1의 "추정(`EstimateFitScaleForViewArea`)" 폐기. 이유: 추정은 fitFactor(0.65/0.70) + BBox 기반인데, 가공도 실제 fit은 `fitRatio = Min(area.W/objW, area.H/objH)` (objW/H = **2D 투영 실측**, fitFactor 없음). 추정≠실측이라 보조선이 또 안 맞음.

**v2 방식 (c)**: 보조선을 **모델 2D 캡처 + RescaleObject 후**, 확정된 `newScale`(`MfgDrawing.cs:329`)로 `ComputeCanvasAbsoluteOffsets(newScale)` → offset 산출 → 그 시점에 그림.
- 추정 오차 0 (실제 배율 사용).
- **순서 재설계**: 보조선 생성을 `BuildMfgSceneCore`에서 **분리**해 `RenderMfgRowToViewArea`의 RescaleObject(`:335`) **이후**로 이동. (현재는 캡처 전 생성)
- 단, 치수 데이터(Osnap·체인) 수집은 `BuildMfgSceneCore`에 남기고, **그리기(DrawDimension)만** 뒤로 이동.

### 4.5 차단 2 — 코드 대조로 완화 (2026-06-03)
제작도 두 경로(`DrawingSheets.cs:1851→1869→1886`, `:2175→2410→2427`)와 가공도(`MfgDrawing.cs:299→335→349`)가 **동일 API·동일 순서**:
① 모델 2D 캡처 → ② `RescaleObject(objId)` 모델만 스케일 → ③ `Add2DObjectFromShapeDrawing` 보조선 후속 추가.

제작도가 이 순서로 보조선이 모델과 정렬되어 화면 일정 → **"보조선↔모델 정렬 메커니즘"은 작동 증거(제작도) 존재.** 가공도가 제각각인 원인은 메커니즘 부재가 아니라 offset 값에 배율 미반영.
→ "방식 자체가 가공도에서 불성립"할 근본 위험은 코드로 해소.

**잔여(눈 확인)**: 가공도는 `MoveObjectTo(objId, cx, cy)`(`MfgDrawing.cs:340`)로 칸 중앙 이동 단계가 추가됨 — 보조선이 이 이동까지 정확히 따라가는지는 **본 작업 단계 2 첫 빌드 결과로 검증**(별도 선행 실기 불요).

## 5. 단계별 (단계 0 선결)

- **단계 0 — 흡수됨 (§4.5)**: 차단 2는 제작도 2경로 동일 순서로 코드 확인 완료. 별도 선행 실기 불요. 보조선↔모델 정렬 미세 검증(`MoveObjectTo` 추종)은 단계 2 첫 빌드 결과에 통합.
- **단계 1 — 공용 헬퍼 + 제작도 교체**: `ComputeCanvasAbsoluteOffsets` 신설, 제작도 `Dimensions.cs:509~513` 교체. 동작 보존. → 제작도 2D 출력 실기 회귀 0 확인.
- **단계 2 — 가공도 순서 재설계 + offset 교체**: 보조선 그리기를 RescaleObject 후로 이동, `newScale` 기반 offset, `offFactor` 제거. 본진(`RenderMfgRowToViewArea`)만.
- **단계 3 — (사용자 결정 시) 풍선 동기화** (§6).
- **단계 4 — 사내 검증**: 제작도 그대로 + 가공도 부재 크기 무관 일정 + 세로 전체 길이 정상.

## 6. 풍선 범위 — 옵션 A 확정 (2026-06-03 사용자)
**보조선만 먼저.** 풍선(100/200 × offFactor_m, `MfgDrawing.cs:866~890`)은 이번 범위 외 — 보조선 검증 완료 후 **같은 기준으로 별도 라운드**. 보조선 통일 직후 풍선이 잠깐 어긋나 보일 수 있음을 사용자 동의함.
