# A2Z 왼쪽 패널 재설계 — 최종 사양서 (검증 반영 확정본)

> 대상: `A2Z/Form1.Designer.cs` 왼쪽 패널 전체(작업 툴바 + 첫 탭 "도면 작업" + 출력 바 + 좌우 분할 폭) 및 3D 화면 위 뷰 툴바
> 범위 밖: 작업·데이터 탭, 부재 정보 탭 내부 (예외 1건 — 부재 목록 재집계 버튼 편입, §4-6)
> 기준: 창 클라이언트 1600 × 1000, 맑은 고딕, 96DPI, .NET Framework 4.8 순정 WinForms, 외부 라이브러리 0
> **본 확정본은 초안 대비 27개 항목이 바뀌었다. 바뀐 목록과 이유는 §10.**

## 1. 설계 원칙

1. **모든 치수·색·폰트는 유한한 토큰에서만 고른다.** 4px 그리드, 회색조 8단계 + 강조색 2개, 폰트 3크기, 버튼 높이 3종. 지금은 버튼 크기 8종·폰트 5종·좌여백 4종·회색 4종이 섞여 "손이 안 간 앱"으로 보인다.
2. **화면은 저절로 움직이지 않는다.** 작업 진행에 따라 영역이 접히거나 커지지 않는다. 구조물 수십 개를 도는 반복 작업에서 가장 비싼 비용은 클릭이 아니라 "버튼이 매번 다른 자리에 있는 것"이다. 접기는 사용자가 누를 때만 일어난다. **단 하나의 예외** — 창을 처음 열 때 화면이 너무 낮으면 구조물 카드가 접힌 상태로 시작한다(§7 밴드 4). 이것은 작업 중 재배치가 아니라 초기 상태 결정이고, 그렇게 하지 않으면 세로가 낮은 노트북에서 출력 버튼이 화면 밖으로 밀린다.
3. **위계는 색이 아니라 위치·크기·활성 상태로 만든다.** 지금은 거의 안 쓰는 뷰 전환 버튼이 가장 화려하고, 최종 산출물을 만드는 출력 버튼 7개가 무채색이다. 이 배분을 뒤집는다.
4. **버튼 좌표와 표 열 폭을 사람이 적지 않는다.** 폭은 전부 균등 분할 컨테이너가 계산하고, 표 열 폭은 실행 중 다시 나눈다. 열 폭 최솟값도 상수가 아니라 **머리글 문자열을 실제로 재서** 정한다. "전체 선택/해제 버튼이 패널 밖에 있는" 유형의 사고와 "머리글이 잘려 무슨 열인지 모르는" 문제를 구조적으로 재발 불가로 만든다.
5. **되돌릴 수 없는 동작과 앱이 멈추는 동작은 형태로 막는다.** 초기화는 자주 누르는 버튼과 다른 줄·다른 높이·다른 색으로 격리하고, 치수 추출 버튼 옆에 "지금 무엇을 대상으로 도는지"를 상시 표시한다. 단 그 표시는 **SDK를 훑지 않고 화면 상태만으로 만들 수 있는 값**이어야 한다(§3-1).

## 3. 영역별 상세

### 3-1. 작업 툴바 (`panelGlobalActions`, Dock=Top, 520×104, 배경 #1E1E20)

| 항목 | 값 |
|---|---|
| 구조 | Padding 12, 내부 TableLayoutPanel(행 40 / 8 / 32) |
| 1행 | 2열 균등, 버튼 `Dock=Fill` + `Margin 4` → 각 **236×40**, 주 버튼 |
| 2행 | `초기화` `Dock=Left` **120×30** (위험-테두리) / 대상 라벨 `Dock=Fill`, `TextAlign=MiddleRight`, F3, #A8A8B0 |

**대상 라벨(`lblDimScope`)의 문구 — 개수를 세지 않는다.**

| 상태 | 문구 |
|---|---|
| 모델 없음 | `모델을 먼저 여세요` |
| 구조물 1개 격리 중 | `대상: FRMWORK-A-01` |
| 구조물 여러 개 체크 | `대상: FRMWORK-A-01 외 2개` |
| 격리 없음 | `대상: 모델 전체 — 오래 걸립니다` |

**왜 개수가 아닌가.** "보이는 부재 24개"를 만들 수 있는 유일한 경로는 모델 전 노드를 돌며 노드마다 화면 표시 여부를 SDK에 묻는 함수뿐이다. 이 함수는 스스로 진행률·취소 확인을 걸 만큼 무겁고, 자주 갱신하면 화면이 멈춘다. 게다가 그 함수는 표시된 부재가 하나도 없으면 **모델 전체를 반환**하고, 치수 추출은 실행 직전에 강조 선택 집합을 비우므로, 라벨이 `0개`인데 실제로는 구역 전체를 도는 — 이 안이 막으려던 바로 그 사고 — 가 라벨을 믿은 상태에서 일어난다. 구조물 이름은 검색·체크 상태만으로 만들 수 있어 SDK 호출이 0이고, 위험한 경우에 정확히 `모델 전체`라고 말한다.

**갱신 시점(이 여섯 곳에서만, 타이머·다시 그리기·가시성 이벤트 구독 금지)**: 모델 열기 성공 후 / 구조물 검색 후 / 구조물 체크 변경 후 / 구조물 목록 선택 변경 후 / 초기화 후 / 전체 보기 후. 같은 문자열을 3D 뷰 툴바의 `lblViewerScope`에도 동시에 넣는다.

**왜 이 배치인가.** 모델 열기와 치수 추출은 탭과 무관한 세션 단위 동작이라 탭 밖 최상단이 맞다. 초기화는 뷰 전환이 아니라 모델을 다시 읽고 그때까지의 작업을 전부 버리는 동작이므로 뷰 버튼 줄 맨 앞자리에서 빼낸다. 자주 누르는 치수 추출 바로 아래가 아니라 **모델 열기 아래**에 두고, 높이(40 vs 30)·형태(채움 vs 테두리)·색(파랑 vs 빨강)을 모두 다르게 해 오버슈트로는 맞지 않게 한다.
**초기화 크기는 120×30으로 확정한다(88 아님).** 격리를 되돌리는 비파괴 수단인 `전체 보기`가 실기에서 완전 복원됨을 확인하기 전까지 초기화를 작게 만들면, 담당자는 여전히 초기화를 찾는데 찾기만 어려워진다. 실기 확인 후 88×30 축소는 별건 후속으로 남긴다.

### 3-2. 탭 (`tabControlLeft`, Dock=Fill)

| 항목 | 값 |
|---|---|
| 설정 | `SizeMode=Fixed`, `ItemSize=(120,28)`, **폰트 미지정**(자식 상속 방지) |
| 화면 문구 | `도면 작업` / `작업·데이터` / `부재 정보` |
| 개발자 탭 | 숨기지 않는다 |
| 개발자 탭 2개 | `AutoScroll = true` 추가 (§8 1단계 — 자동 배율 해제로 내부가 designer 좌표대로 커져 아래가 잘릴 수 있다) |

### 3-3. 구조물 카드 (`panelStruCard`, Dock=Top, 512×268)

| 줄 | 높이 | 내용 | 정렬 |
|---|---|---|---|
| 헤더 바 | 32 | `▼` + `구조물 목록` + 우측 `12개 · 3개 선택` | 라벨 좌 8px, 개수 우 12px |
| 검색 줄 | 42 | 입력창 `Dock=Fill` H=25(폭 408) + `찾기` 72×30 | Padding(12,8,12,9) |
| 목록 | 152 | `clbStruList`, 테두리 없음 | Dock=Fill, 좌우 여백 0 |
| 액션 줄 | 42 | `전체 선택/해제` · `전체 보기` · `한 번에 출력 (3)` 3열 균등 **154×30** | Padding(12,6,12,6) |

- 검색은 목록의 **입력**이므로 결과(목록) 위에 온다. 지금은 목록 아래에 붙어 읽는 순서와 반대다.
- 입력창 안내 문구는 `EM_SETCUEBANNER`(0x1501)로 넣는다. 이 방식은 안내 문구가 `Text`에 들어가지 않으므로 아무것도 입력하지 않고 `찾기`를 눌렀을 때 `검색할 이름을 입력해주세요`가 정상적으로 뜬다. 손수 만든 회색 글씨 방식은 안내 문구가 그대로 검색어로 새어 나가므로 쓰지 않는다.
- `전체 보기`는 검색으로 걸린 격리를 되돌리는 유일한 비파괴 수단이다. 지금은 개발자 탭 안에만 있어 담당자가 격리를 풀려고 파괴적인 초기화를 눌러 왔다. **단, 기존 핸들러는 전체를 복원하지 못한다 — §4-4의 새 핸들러 사양을 반드시 함께 구현한다.**
- `한 번에 출력 (3)`은 출력 바의 큰 버튼과 같은 동작이다. 체크 직후 손이 머무는 자리의 지름길. 괄호 숫자는 체크가 바뀔 때마다 갱신된다.
- 헤더 바 클릭 시 카드가 32px로 접히고 문구가 `▶ 구조물 목록 · FRMWORK-03 외 2개`로 바뀐다. 접어도 체크 상태는 유지된다(높이만 바꾼다).

## 7. 왼쪽 패널 폭 · 창 크기

### 폭 확정: **520px** (현재 457px, +63px)

```
490   부재 목록 8열 폭 합 (첫 열 아이콘 16 포함)
+  5   가로 스크롤 방지 여유
+ 17   세로 스크롤바
─────
 512   표 폭 = 탭 페이지 폭
+  8   탭 컨트롤 테두리 (4 × 2, 실측 확인)
─────
 520   splitContainer1.SplitterDistance
```

패널 폭을 정하는 것은 취향이 아니라 부재 목록 8열이다. 현재 457px에서는 클라이언트가 422px뿐이라 8열(505px)이 83px 넘쳐 MA·FA가 화면 밖에 있다. 457은 "조금 좁은" 게 아니라 **설계상 담을 수 없는 폭**이다.

**필수 설정 — Designer의 BeginInit/EndInit 구간 안에 넣는다**

```csharp
splitContainer1.FixedPanel    = FixedPanel.Panel1;
splitContainer1.Panel1MinSize = 460;
splitContainer1.Panel2MinSize = 640;
splitContainer1.SplitterWidth = 6;
splitContainer1.SplitterDistance = 520;
```

런타임(`Form1.cs`)에 두면 컨트롤 폭이 1106 미만인 순간 `Panel2MinSize` 대입이 예외로 죽는다(실측). Designer 구간에서는 검증이 억제된다.

**Load 후 1회 폭 조정 — 반드시 직접 클램프**

```csharp
int want = (int)(splitContainer1.Width * 0.33);
int lo   = splitContainer1.Panel1MinSize;
int hi   = splitContainer1.Width - splitContainer1.SplitterWidth - splitContainer1.Panel2MinSize;
splitContainer1.SplitterDistance = Math.Max(lo, Math.Min(Math.Min(560, hi), Math.Max(460, want)));
```

범위를 벗어난 대입은 예외 없이 **조용히 클램프**되므로(실측), 값을 직접 계산하지 않으면 의도한 폭과 다른 값이 들어가고도 알 수 없다.

| 창 클라이언트 폭 | 왼쪽 | 3D | 비고 |
|---|---|---|---|
| 1164 (최소창 1180의 클라이언트) | **518** | 640 | 오른쪽 최소(640)에 먼저 걸려 왼쪽이 눌린다 |
| 1280 | 634 → 클램프 **560** | 714 | ✅ |
| 1600 (기본) | **520** | 1074 | 설계 기준 |
| 1920 | **560** | 1354 | 왼쪽 상한 |
| 2560 | **560** | 1994 | 늘어난 폭은 전부 3D |

460에서도 재배분 함수가 비율로 다시 나누므로 가로 스크롤은 생기지 않는다(기준 부재·SIZE가 말줄임으로 바뀔 뿐).

### 창 크기 결함 수정

```csharp
this.AutoScaleMode = AutoScaleMode.None;          // §5-2
var wa = Screen.PrimaryScreen.WorkingArea;
this.MinimumSize = new Size(1180, 620);
this.ClientSize  = new Size(Math.Min(1600, wa.Width  - 40),
                            Math.Min(1000, wa.Height - 60));
```

- 가로 1180은 `460 + 6 + 640 = 1106` + 테두리 때문에 유지한다.
- **세로 하한은 760이 아니라 620이다.** 이 앱은 고해상도 인식을 선언하지 않으므로 1920×1080 150% 노트북이 보고하는 논리 화면은 1280×720이고 작업 표시줄을 뺀 작업영역 높이는 약 688이다. 하한 760은 바깥 크기 기준이라 688보다 72px 커서, 초안대로 하면 "창이 화면을 넘어 출력 버튼이 잘린다"는 결함이 그대로 남는다.
- 그 노트북에서의 결과: 클라이언트 628 → 탭 페이지 488 → 아래 밴드 4 → 구조물 카드는 접힌 채 시작, 도면 목록 6행, 부재 목록 2행, **출력 바까지 전부 화면 안**.

| 밴드 | 구조물 목록 | 구조물 카드 | 부재 표 | 도면 표 (밴드 기준 높이) |

| 700 ≤ H < 820 | 98 (5행) | 214 | 120 (4행) | H−552 → 760일 때 208 (8행) / 700일 때 148 (5행) |
| 560 ≤ H < 700 | 62 (3행) | 178 | 78 (2행) | H−474 → 620일 때 146 (5행) |

- 구간이 바뀔 때만 동작하고, 사용자가 손으로 접거나 분할선을 옮긴 뒤에는 그 값을 존중한다.

- **안전망**: `tabPageDrawing.AutoScroll = true`, `AutoScrollMinSize = (0, 430)`. H가 430보다 낮아지는 극단(사용자가 창을 하한까지 줄이고 구조물 카드를 손으로 펼친 경우)에서만 세로 스크롤이 생겨 계산이 음수로 무너지는 일을 막는다. 가로는 0으로 두어 가로 스크롤은 생기지 않는다.

```
        A2Z/Form1.Stru.cs:732-741       (일괄 출력 종료 — 이 경로는 상태 복원 쌍을
                                         쓰지 않고 버튼 Enabled를 직접 되돌리므로
                                         빠뜨리면 도면 목록이 가득 차도 단계 1에 머문다)
```

> **이 규칙이 없으면 앱이 도면을 못 뽑는다.** `SetDrawingExportControlsEnabled(true)`를 부르는 곳이 저장소 전체에 0건이고, 유일한 복귀 수단인 상태 복원 함수는 작업 시작 시점에 읽어 둔 값을 그대로 되돌려 쓴다. 생성자에서 그냥 꺼 두면 치수 추출이 "꺼짐"을 캡처해 "꺼짐"으로 복원하고, 출력 버튼 7개가 영구히 죽는다.
> 또한 컨트롤의 `Enabled` 읽기 값은 부모가 꺼져 있으면 함께 꺼진 것으로 읽히므로, **부모 패널을 통째로 끄는 방식은 쓰지 않는다.**

각 단계 끝에서 **커밋 + push**한다. 사용자는 다른 PC에서 실기 검증하므로, push되지 않은 변경분은 검증에 도달하지 못한다.

## 9. 버리는 것과 그 이유

### 삭제

| 대상 | 이유 |
|---|---|
| 도면 목록 위 설명 문구 | 내부 알고리즘 이름이라 담당자에게 전달되는 정보가 0이고 실행 중 갱신도 되지 않는다. 세로 20px과 함께 제거 |
| `도면 시트 목록` 헤더 패널(55px) | 카드마다 헤더 바가 생겨 완전히 중복. 제목·설명 두 라벨이 설계상 1px 겹쳐 있어 배율이 조금만 달라지면 실제로 겹친다 |
| GroupBox 캡션 `STRU 목록 (모델트리)` | 바로 아래 라벨이 같은 말에 개수까지 붙여 표시한다. 제목 하나에 세로 51px 쓰던 것을 32px로 |
| 검색 UI를 실행 중에 만들던 코드 | 화면에 없는 컨트롤이 코드로 생겨 Designer와 충돌하고, 목록 아래에 붙어 읽는 순서가 뒤집혀 있었다 |
| `슬롯홀` 열 잔재 | 선언만 되고 어떤 표에도 추가되지 않는다 |
| `포함 부재` 열의 전체 나열 | 부재 25개면 462px이 필요해 어떤 폭에서도 잘린다. 잘릴 것을 전제로 마지막 열에 두고 전문은 툴팁으로 |
| **"보이는 부재 N개" 개수 표시** | 값을 만드는 유일한 경로가 모델 전 노드를 훑는 무거운 스캔이고, 정작 위험한 상황(표시된 부재 0건)에서 `0개`라고 표시하면서 실제로는 모델 전체를 돈다. 범위 이름 표시로 대체 (§3-1) |

### 이동

| 대상 | 어디로 | 이유 |
|---|---|---|
| 부재 목록 재집계 버튼 | 작업·데이터 탭 BOM 그룹 하단 | 시트를 고르거나 도면을 그릴 때 자동으로 다시 집계된다. 다만 "시트를 안 고른 상태에서 모델 전체 집계"라는 고유 경로가 있어 삭제가 아니라 이동. 문구를 `BOM 다시 모으기`로 바꿔 같은 탭의 기존 `BOM` 버튼과 구분한다 |
| 초기화 | 뷰 버튼 줄 맨 앞 → 작업 툴바 2행 왼쪽 | 뷰 전환이 아니라 모델을 다시 읽고 그때까지의 작업을 전부 버리는 동작이다. 가장 누르기 쉬운 좌상단 첫 자리에 둘 이유가 없다. **크기는 줄이지 않는다**(§3-1) |
| 가공도 | 미리보기 줄 → 종류별 출력 줄 | 나머지 셋과 성격이 완전히 같은데 혼자 다른 줄에 있었다 |
| `화면에 그리기` · `PDF로 저장` | 출력 바 → 도면 목록 카드 바로 아래 | 둘 다 "표에서 고른 한 장"에 대한 동작인데 표에서 세로 400px 떨어져 있고 그 사이를 부재 목록이 가로막고 있었다 |
| ISO · X · Y · Z | 3D 화면 위 툴바 | 3D를 보면서 방향을 바꾸는 동작이다. 왼쪽은 작업 흐름, 오른쪽은 보기 조작으로 역할을 가른다 |

### 축소

| 대상 | 이유 |
|---|---|
| 부재 목록 14행 → 6행 | 이 표는 입력이 아니라 3D를 조종하는 조회용이다. 319px 점거하던 것을 164px로 줄여 도면 목록에 넘긴다. 대신 8열 전부가 처음으로 보이고, 분할선으로 언제든 되돌릴 수 있으며 그 높이가 유지된다. **"많이 보기"를 "온전히 보기"와 맞바꾼 것** |

| 3D 화면 1138 → 1074 (−5.6%) | 부재 목록 8열을 자르지 않으려면 피할 수 없다. 대신 왼쪽을 고정폭으로 묶어, 창을 키우면 늘어난 폭이 전부 3D로 간다 |
| 축 버튼의 색 블록 | 각 2400px²의 원색 블록이 시선을 독점해 최종 산출물을 만드는 출력 버튼이 무채색으로 묻혔다. 배경은 회색으로 낮추고 글자색만 축 색으로 남긴다. 익숙한 사용자는 처음 며칠 색 블록을 눈으로 찾을 수 있다 — 이 안이 지불하는 가장 직접적인 비용이다 |

### 하지 않는 것 (의도적 포기)

| 항목 | 이유 |
|---|---|
| 개발자 탭 숨기기 + 복원 단축키 | 발견 가능성이 0인 단축키를 팀 전원이 매 실행마다 눌러야 한다. 탭 줄 28px을 지불하고 기계장치를 없앤다 |
| 작업 단계에 따른 자동 접기 | 화면이 매번 재배치되면 버튼 위치를 손이 외울 수 없다. 접기는 사용자가 누를 때만 (창이 낮을 때의 초기 상태 1회는 예외, §1) |
| 표 머리 클릭 정렬 | 행 순서를 바꾸면 일괄 출력이 전제하는 순서가 깨진다. 대신 머리를 클릭 불가로 만들어 기대 자체를 없앤다 |
| 선택 행 색 커스터마이즈 | 표 렌더링을 전면 인수해야 한다. 시스템 강조색을 쓴다(직접 그리기를 켜도 선택 강조는 유지됨을 확인) |
| 표 열 머리 높이 조절 | 어떤 방법으로도 불가능하다. 24px을 전제로 모든 행 수를 계산했다 |
| 선택 탭 색상 | 직접 그려도 탭 줄 오른쪽 여백이 시스템 회색으로 남아 오히려 어설퍼진다 |
| 버튼 둥근 모서리 | 순정 방식은 안티앨리어싱이 없어 모서리가 계단처럼 깨진다 |
| 아이콘 이미지 | 저장소에 UI 아이콘 자산이 없다. 필요한 곳은 문자(`▼ ▶`)로 |
| 고해상도 인식 선언 | 켜는 순간 3D 뷰어 좌표가 어긋날 위험이 있다. 창 크기 제한 + 자동 배율 해제로 증상이 해소된다 |
| 부재 목록 8열의 이름·순서 변경 | 출력 도면의 표가 이 순서를 인덱스로 읽고, 담당자가 화면과 인쇄물을 대조해야 한다 |
| 도면 목록 첫 열 값 변경 | 저장 PDF 파일명과 가공도 분기 판정에 그대로 쓰인다 |
| 폼 폰트 일괄 지정 | 자식 전부가 상속받아 행 높이와 열 머리 24px 전제가 흔들린다 (초안 철회, §5-2) |
