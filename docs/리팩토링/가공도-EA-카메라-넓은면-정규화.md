## 1. 문제 (은선 폐지로 드러남)

앵글(ㄱ자) 부재의 가공도 두 뷰가 부재마다 **찍는 방향이 제각각**이다:

- 기대: 항상 **ㄱ자의 위에서 한 번, 오른쪽에서 한 번** — 두 플랜지를 각각 정면으로.
- 실제: "아래서+왼쪽에서 찍은 듯한 부재", "아래서+오른쪽에서 찍은 듯한 부재"가 섞여 나옴.

은선 포함 시절엔 앞뒤 모서리가 다 그려져 방향 차이가 눈에 안 띄었는데, **단면(보이는 외곽선)만 그리자 카메라가 어느 쪽에서 찍었는지가 그대로 드러남**.

## 2. 왜 뒤죽박죽인가 — 현행 메커니즘

현재 EA 카메라·배치는 서로 다른 기준의 휴리스틱 3개가 겹쳐 있다:

| 단계 | 현행 기준 | 위치 |
|---|---|---|
| 1차 뷰 ± 방향 | "열린 방향" 보정 — osnap 중심 vs BBox 중심 비교로 PLUS/MINUS 선택 + R180 | `BuildMfgSceneCore` L1150~1199 |
| 2차 뷰 방향 | 고정 (`Z_MINUS`, Z최장이면 `X_PLUS`) | `BuildEaSecondaryScene` L578~596 |
| 상하 배치·반전 | 접힘 코너 판정 → SwapViews + 2차 뷰 MirrorVertical | 코어 5-2a + `BuildEaSecondaryScene` |

문제의 근원 2가지:

1. **기준 불일치**: "열린 방향"(osnap 쏠림), "코너 위치", "고정 카메라"가 각각 따로 놀아, 부재의 세계좌표 방향에 따라 조합 결과(패리티)가 섞인다.
2. **캡처가 카메라 ±방향을 무시** (실기 확정, 2026-06-29 `9f38521`): `MoveCamera(X_PLUS)`든 `X_MINUS`든 2D 캡처 결과가 같음. 즉 1단계에서 ±를 애써 골라도 **PDF에는 반영이 안 되고**, 스왑·미러가 그 어긋남을 사후 보정해온 구조.
   - ⚠️ 단, 이 확정은 **옛 은선 캡처**(`...WithModelHiddenLine...`) 기준. 새 단면 캡처(`Create2DViewObjectWithModelAtCanvasOrigin`)도 같은지 **재검증 필요** (§5-1).

## 3. 제안 알고리즘 (사용자 안 정식화)

용어: 길이축 = 부재 최장축(두 뷰 모두 화면 가로). 나머지 두 축 = 교차축 B·C.
"**보이는 면 넓이**" = 후보 카메라에서 봤을 때 **그대로 보이는 가장 가까운 면**의 넓이 (사용자 정정 2026-07-03 — 끝 절단면(단면) 아님).
계산 = 그 축의 카메라 쪽 극단 깊이 슬랩에 있는 osnap들의 **나머지 2축 bounding 사각형 넓이** (앵글 플랜지 면 = 사각형이므로 네 모서리 osnap으로 충분).

```
0. 가로 배치(landscape)는 지금 그대로 (ProbeAndRollLandscape).
1. [1차 뷰 방향] 1차 카메라 축의 양쪽에 대해
   이쪽에서 봤을 때 보이는 가까운 면 넓이 vs 반대쪽에서 봤을 때 보이는 가까운 면 넓이
   → 보이는 면이 더 넓은 쪽에서 찍는다.
   (예: 플랜지 면 L×50 vs 반대쪽에선 얇은 변 L×8만 보임 → 50쪽에서 찍음)
2. [2차 뷰 방향] 1차 뷰의 화면-위/아래 축에서
   위에서 봤을 때 보이는 면 넓이 vs 아래에서 봤을 때 보이는 면 넓이
   → 넓은 쪽에서 찍음 (위에서 or 아래에서). 동률이면 직육면체라 어느 쪽이든 무관.
3. [슬롯 배치]
   - 2차 카메라가 '위에서' 찍었으면 → 1번(위) 슬롯 = 2차(위에서 본) 뷰,
                                        2번(아래) 슬롯 = 1차 뷰.
   - '아래에서' 찍었으면            → 1번(위) 슬롯 = 1차 뷰,
                                        2번(아래) 슬롯 = 2차(아래에서 본) 뷰.
   (투영 전개 관례와 동일 — 위에서 본 그림은 위에, 아래에서 본 그림은 아래에)
4. [길이 방향 좌우] 두 뷰의 좌우(어느 끝이 화면 왼쪽인지)는 반드시 일치시킨다.
   어느 끝을 왼쪽에 둘지 표준은 없음 — 일치만 보장하면 됨 (확정 2026-07-03).
```

핵심: **모든 방향 결정을 "카메라 쪽에 넓은 면" 단일 기준으로 통일**. ㄱ자라면 자동으로 "위에서 + 옆(넓은 플랜지 쪽)에서"가 되고, 부재가 세계좌표에서 어떻게 놓였든 출력 모양이 같아진다.

## 4. 대체·단순화되는 기존 로직

| 기존 | 새 알고리즘에서 |
|---|---|
| 열린 방향 보정 (osnap 중심 vs BBox 중심) + R180 | **폐기** → 1단계 넓이 비교로 대체 |
| 접힘 코너 판정 (CornerAxis/SecCorner*) + SwapViews | **폐기** → 3단계 슬롯 규칙으로 대체 |
| 2차 뷰 MirrorVertical (혼합 패리티 사후 보정) | **원칙적으로 불필요** — 방향이 처음부터 맞으면 뒤집을 일 없음. 단 §5-1 결과에 따라 '구현 수단'으로는 남을 수 있음 |
| 길이 치수 = 위 슬롯 뷰가 그림 | **유지** (슬롯 결정 후 동일 적용) |
| 폭 치수 화면 오른쪽(MfgHeightToRight) | **유지** (방향 정규화 후엔 판정이 더 단순해질 여지) |

부수 효과: `MfgViewPose`의 코너 관련 6필드(HasCorner/CornerAxis/CornerAtMax/HasSecCorner/SecCornerAxis/SecCornerAtMax)와 SwapViews/CornerAxisUp/MirrorVertical이 대폭 정리될 수 있음.

## 5. 구현 제약과 방식 후보 (개발 전 확인 필요)

### 5-1. 선결 검증: 새 단면 캡처가 카메라 ±를 반영하는가
- 옛 은선 캡처는 ± 무시 확정. **새 캡처도 무시하면** "반대쪽에서 찍기"를 `MoveCamera`로 구현할 수 없다.
- 검증 방법: 같은 부재를 `X_PLUS`/`X_MINUS`로 각각 probe 캡처해 결과 비교 (사내 1회 실기 또는 DiagLog 좌표 비교).
- **반영 안 될 경우의 구현 수단** (검증된 것만):
  - 화면축 180° roll (`RotateCameraByScreenAxis` — 캡처 반영 확정) = 상하+좌우 동시 반전
  - 2D 미러 (`SetSelected3DMirrorBy2DView` — 치수 매핑까지 함께 뒤집힘 확정) = 한 축 반전
  - 조합하면 4가지 패리티 모두 도달 가능 → "원하는 모양"을 먼저 정의하고, 고정 투영이 만드는 모양과의 차이를 roll/미러로 맞추는 방식
- 주의: ±가 캡처에 반영 안 되면 **"어느 면이 실제로 그려지는가"(가까운 면)는 고정 투영이 결정**한다. 이 경우 넓이 비교의 역할은 "찍는 방향 선택"이 아니라 "**그려질 면을 예측하고, 원하는 모양과 다르면 반전 보정**"으로 바뀐다. 알고리즘 골격(넓이 기준·슬롯 규칙)은 동일.

### 5-2. 보이는 면 넓이 계산
- 재료는 이미 있음: osnap 수집 + 깊이 슬랩 분리(`FilterHiddenLineOsnap`의 15% 슬랩 로직과 동일 패턴).
- 카메라 쪽 극단 슬랩(허용오차 내) osnap의 2축 extent 곱 = 그 방향에서 보이는 가까운 면의 bounding 넓이. 앵글 플랜지면은 사각형이라 충분.
- 홀 osnap이 섞여도 bounding엔 무해. 대각(beveled) 부재는 bounding이 실제보다 크게 나오지만 **비교(어느 쪽이 넓은가)** 용도라 대개 무해.

### 5-3. 안전장치
- 슬랩에 osnap이 너무 적으면(<3) 비교 불가 → 기본 방향 규칙으로 폴백.
- 검증은 EA 부재만 대상 (일반 부재 단일 뷰는 §6-Q2 결정 전 현행 유지).

## 6. 질문 상태 (2026-07-03 사용자 답변 반영)

- **Q1 — 확정**: 동률이면 아무 쪽이나 (구현은 +축 쪽 고정 규칙 채택 예정). 위/아래도 넓은 쪽에서, 동률이면 직육면체라 무관.
- **Q2 — 확정**: **일반 부재 단일 뷰도** "넓은 면이 카메라 쪽" 동일 적용.
- **Q4 — 확정**: 1번 = 위 슬롯 / 2번 = 아래 슬롯. "길이 치수는 위 슬롯 뷰가 그린다" 유지.
- **Q3 — 확정** (2026-07-03, 재설명 후):
  - 측면 뷰 카메라를 왼쪽/오른쪽 어디서 찍을지는 **1단계 넓이 규칙이 이미 해결** (ㄱ자 세로 플랜지의 '면'이 보이는 쪽 = 오른쪽에서. 왼쪽에서 찍으면 가까운 게 얇은 변 8뿐이라 탈락).
  - 남은 자유도였던 **길이 방향 좌우**(어느 끝이 화면 왼쪽인가):
    - **Q3-a 확정**: 두 뷰의 좌우는 **반드시 일치** (어긋나면 같은 홀이 위·아래 뷰에서 반대쪽에 보임).
    - **Q3-b 확정**: 어느 끝을 왼쪽에 둘지 **표준 없음** — 두 뷰 일치만 보장하면 됨.
