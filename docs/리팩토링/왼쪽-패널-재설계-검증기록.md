### 제거위험 — 조건부통과
- [중대] **도면 목록 열 순서를 바꾸라고 해놓고, 그 열을 채우는 코드의 순서를 바꾸라는 지시가 없다 — 값이 엉뚱한 열에 들어간다**
  - 근거: 실제 열 순서는 A2Z/Form1.Designer.cs:244-248 기준 `colSheetNo, colSheetBase, colSheetMembers, colSheetCount` = 도면번호 / 기준부재 / **포함부재** / **부재수** 다. 값 채우기는 A2Z/Form1.DrawingSheets.cs:297-299에서 `new ListViewItem(sheetLabel)` → `SubItems.Add(baseText)` → `SubItems.Add(includedText)`, 그리고 :458에서 `SubItems.Add(countText)` 순이다. 그런데 사양서 §2-2 배치도와 §6-1 표는 `도면번호 / 종류 / 기준 부재 / 부재 / 포함 부재` 순을 요구한다(부재수가 포함부재보다 앞). §4-5는 `colSheetMembers`에만 "순서이동 — 마지막 열"이라 적었을 뿐, DrawingSheets.cs의 SubItems 채우기 순서를 재작성하라는 조항이 §4-5·§6-1·§8 어디에도 없다. Columns.AddRange만 바꾸면 포함부재 문자열(`1, 2, 3 …`)이 폭 46짜리 "부재" 열에, 부재수 숫자가 폭 136짜리 "포함 부재" 열에 표시된다. 여기에 종류 열을 인덱스 1로 끼워 넣으면 뒤 열 전부가 한 칸씩 더 밀린다. (다행히 크래시는 없다 — 저장소 전체에서 lvDrawingSheet 항목을 SubItems 인덱스로 읽는 코드는 0건이고 .Text/.Tag만 쓴다. 즉 순수 표시 오류다.)
  - 수정: §4-5 표와 §8 3단계에 조항을 추가: "A2Z/Form1.DrawingSheets.cs:297-299 및 :458의 SubItems 구성을 `sheetLabel(=lvi.Text, 불변) → kindText → baseText → countText → includedText` 순으로 재작성한다". 종류 문자열은 `sheet.BaseMemberIndex`(-3 가공도 / -2 설치도 / -1 전체) 분기와 sheetLabel 접두사로 판정하고, 첫 열 값은 절대 손대지 않는다. 열 폭 재배분 함수 `ResizeSheetColumns()`의 고정폭 목록도 이 순서와 일치시킨다.
- [중대] **'전체 보기'를 격리 해제 수단으로 승격했지만, 재사용하겠다는 핸들러가 실제로는 전체 복원을 못 한다 — 초기화를 눈에 덜 띄는 자리로 옮기는 근거가 무너진다**
  - 근거: §4-4는 신설 `btnStruShowAll`과 §3-7의 뷰 툴바 `btnViewShowAll`이 `btnClashShowAll_Click`을 추가 구독한다고 했다. 그 핸들러(A2Z/Form1.Drawing2D.cs:649-687)의 가시성 복원은 `RestoreAllPartsVisibility()` 한 줄뿐인데, 이 함수(A2Z/Form1.MfgDrawing.cs:23-32)는 `foreach (BOMData b in bomList) allIndices.Add(b.Index); if (allIndices.Count > 0) vizcore3d.Object3D.Show(allIndices, true);` 로 **bomList에 담긴 인덱스만** 다시 켠다. bomList는 `GetBOMTargetNodes`(A2Z/Form1.BOM.cs:778-818)가 `realNode.Visible` 로 걸러 채운다(:811-813). 한편 구조물 검색(A2Z/Form1.Stru.cs:295-305)은 `Object3D.Show(allBodyIndices, false)` 로 전체 BODY를 숨긴 뒤 해당 구조물만 켠다. 따라서 사양서가 지목한 바로 그 경로 — 검색으로 격리 → 치수 추출 → 전체 보기 — 에서는 bomList에 격리된 구조물 부재만 들어가고, 전체 보기를 눌러도 나머지 모델은 계속 숨겨진 채 남는다. 모델을 열자마자 검색만 한 경우엔 bomList가 비어 `allIndices.Count == 0` 이라 Show 호출조차 일어나지 않는다(bomList를 채우는 CollectBOMData 호출은 BOM.cs:396 / BOM.cs:1047 / Dimensions.cs:2125 / Stru.cs:843 넷뿐이고 모델 열기 시점엔 없다). §3-3과 §9는 "담당자는 격리를 풀려고 파괴적인 초기화를 눌러 왔다"를 근거로 초기화를 좌상단 첫 자리에서 빼내는데, 그 대체 수단이 동작하지 않으므로 사용자는 그대로 초기화를 찾게 된다.
  - 수정: 신설 버튼 2개를 `btnClashShowAll_Click`에 그대로 붙이지 말고, 새 핸들러를 만들어 `vizcore3d.Object3D.FromFilter(Object3dFilter.ALL_INCLUDE_BODY, false)` 로 전 BODY 인덱스를 모아 `Show(list, true)` 하는 단계를 **먼저** 넣고 그 위에 기존의 X-Ray 해제·`xraySelectedNodeIndices.Clear()`·색 복원·심볼 제거·SilhouetteEdge 복원·FitToView·ShowAllDimensions를 얹는다. 개발자 탭 `btnClashShowAll`도 같은 새 핸들러로 교체(현재도 같은 결함을 안고 있다). 실기에서 전체 복원이 확인되기 전까지는 §3-1의 초기화를 88×30으로 축소하지 말고 현재 크기·눈에 띄는 자리를 유지한다.
