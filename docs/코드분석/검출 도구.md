## 검사 1 — 배선 검사 (`grep`)

### 왜 필요한가

이벤트 핸들러는 **코드가 직접 부르지 않는다.** `+=` 로 버튼에 연결해 두면 사용자가 누를 때
프레임워크가 부른다. 그래서 「호출처 0건」으로 보여도 살아 있는 게 정상이다.

**뒤집으면** — 연결(`+=`)이 없으면 그 함수는 **어떤 방법으로도 안 불린다.**

### 어떻게 했나

이름으로 코드 전체를 훑고, 그 결과에 `+=` 가 있는지 본다.

```bash
grep -rn "btnOpen_Click" --include=*.cs A2Z/
```

### 실제 대조 — 산 것과 죽은 것

**살아 있는 핸들러** `btnOpen_Click`

```
Form1.BOM.cs:182       private void btnOpen_Click(object sender, EventArgs e)      ← 정의
Form1.BOM.cs:284       /// btnOpen_Click의 초기화 블록과 동일하되 …                ← 주석
Form1.Designer.cs:1202 this.btnOpen.Click += new System.EventHandler(this.btnOpen_Click)
                                          ↑ 배선 1건 — 살아 있다
```

**죽어 있던 핸들러** `btnShowAxisX_Click` (삭제 전 커밋 `a10e81a` 기준)

```
Form1.Dimensions.cs:205   private void btnShowAxisX_Click(object sender, EventArgs e)   ← 정의뿐

  += 배선: 0건   ← 화면에 버튼이 있어도 눌러서 여기로 올 길이 없다
```

### 한계

이름이 흔하면 엉뚱한 게 걸린다. `Designer.cs` 의 주석·문자열도 같이 잡힌다.
**후보만 뽑고 사람이 확인한다.**

### 주요 기능

**① 메서드 전수 추출** — 정규식으로 선언을 찾고, 중괄호를 세어 본문 끝까지 잡는다.

```python
RE_METHOD = re.compile(
    r'^\s*(?:\[[^\]]*\]\s*)?'                                   # [Attribute]
    r'(?:private|public|protected|internal)\s+'                 # 접근제한자
    r'(?:static\s+|async\s+|override\s+|virtual\s+|…)*'          # 수식어
    r'(?:[\w<>\[\],\.\?]+…\s+)'                                 # 반환형
    r'([A-Za-z_]\w*)\s*\('                                      # ← 이름
)
```

`brace_end()` 가 `{` `}` 를 세어 본문의 끝 줄을 찾고, `nested_type_spans()` 로
**중첩 타입 안쪽은 제외**한다 (데이터 클래스의 속성을 메서드로 세지 않으려고).

**② 호출처 세기** — 이름 뒤에 `(` 가 붙은 것만 호출로 본다.

```python
def count_calls(files, name, home):
    pat = re.compile(r'(?<![\w.])' + re.escape(name) + r'\s*\(')
    hits = []
    for f, lines in files.items():
        c = len(pat.findall("\n".join(lines)))
        if f == home:
            c -= 1                      # 선언 자신 제외
        if c > 0:
            hits.append((f, c))
    return hits
```

- `(?<![\w.])` — 앞에 글자나 점이 붙은 건 제외. `this.Foo(` 나 `BarFoo(` 를 안 센다
- 선언한 파일에서는 **1을 빼서** 정의 자신을 제외
- `callers` 가 비면 **「불리는 곳 없음」 = 죽은 코드 후보**

**③ 필드도 같은 방식** — 여러 파일이 **값을 바꾸는** 필드를 센다 (2026-08-31 기준 변경).
읽기만 하는 것은 제외한다 — SDK 핸들을 모든 파일이 읽는 건 구조상 당연하다.

## 검사 3 — 호출 그래프 도달성 (`reach.py`)

`docs/코드분석/reach.py` 74줄 · 실행 `python docs/코드분석/reach.py`

### 왜 필요한가

`grep` 은 **「누가 부르긴 부른다」**만 본다. 그 부르는 쪽이 이미 죽었으면 모른다.
도달성은 **시작점에서 출발해 실제로 닿는지**를 본다.

### 4단계

```
① 메서드 전수 + 본문 수집          정규식 + 중괄호 세기
        ↓
② 호출 그래프 만들기               본문에서 다른 메서드 이름을 뽑아 간선으로
        ↓
③ 진입점 모으기                    Designer 배선 + 코드 배선 + 생성자 + 프로퍼티
        ↓
④ 너비우선으로 퍼뜨리기            진입점에서 닿는 것을 전부 칠하고, 안 칠해진 것이 고아
```

```python
# ④ 도달성
seen, stack = set(), list(entries)
while stack:
    c = stack.pop()
    if c in seen: continue
    seen.add(c)
    stack.extend(calls.get(c, ()))
orphan = names - seen          # ← 어떤 경로로도 도달 불가
```

### 진입점을 무엇으로 보나

여기가 이 스크립트의 핵심이다. **진입점을 잘못 잡으면 멀쩡한 함수가 고아로 나온다.**

| | 어디서 |
|---|---|
| Designer 배선 | `+= new EventHandler(this.이름)` |
| 코드 배선 | `+= 이름;` · `+= new Action(이름);` |
| **생성자가 부르는 것** | `public Form1()` 본문 — 반환형이 없어 메서드로 안 잡히므로 따로 |
| **프로퍼티가 부르는 것** | `get { return 이름(...); }` |

### 보정한 오탐 4종 (2026-08-31)

최초 실행의 고아 9개 중 7개가 오탐이었다. 원인을 다 찾아 스크립트에 반영했다.

| 오탐 | 원인 | 예 |
|---|---|---|
| 생성자에서 부르는 것 | `public Form1()` 은 **반환형이 없어** 메서드 정규식에 안 걸린다 | `SetupBOMColumns` · `SetupAttributeColumns` · `LogBuildStamp` |
| 이름만 넘기는 호출 | `new Action(이름)` — **괄호가 안 붙어** 호출로 안 보인다 | `StartNextSilentClashTestAfterEvent` (`Clash.cs:1014`) |
| 프로퍼티 본문 | `get { return 이름(...); }` 를 안 봤다 | `NormalizeMfgAxisVector` |
| 정규식 오탐 | `private static readonly (string, int)[] X =` 를 선언으로 오독 | `readonly` 가 함수 이름으로 잡힘 |

> ⚠ **문서 정정.** 이전 판은 「도달성은 `BeginInvoke(new Action(이름))` 을 잡는다」고 적었으나
> **최초 스크립트도 못 잡았다.** 고아로 나온 것을 사람이 확인해 살아 있음을 알아낸 것이다.
> 스크립트가 아니라 판독이 막았다. 8/31 보정으로 이제 스크립트도 잡는다.

### 한계

- **리플렉션·문자열로 부르는 것**은 원리적으로 못 잡는다

- 고아로 나와도 **지우기 전에 반드시 확인**한다 — 최초 실행에서 9개 중 7개가 오탐이었다
