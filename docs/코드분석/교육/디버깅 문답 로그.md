### Q1. 메서드 시작부터 — `object sender` 와 `EventArgs e` 각각 하는 역할

**A.**

**`object sender` = 이 이벤트를 일으킨 물건.** 여기서는 `btnExtractDrawingList` 버튼 자신.

```csharp
// Form1.Designer.cs:485 — 여기서 이어붙였다
this.btnExtractDrawingList.Click += new System.EventHandler(this.btnExtractDrawingList_Click);
//   └─ 이 버튼이 ─────────────────────────────────────────┘  sender 로 들어온다
```

- 버튼 여러 개가 **같은 함수 하나**를 쓸 때 「어느 버튼이 눌렸나」를 구분하는 용도
- 타입이 `object` 인 이유 — 버튼·목록·타이머 무엇이든 올 수 있어서. `object` 는 모든 타입의 조상

**`EventArgs e` = 이벤트에 딸려 오는 추가 정보.** `Click` 은 알려줄 게 없어 **빈 객체**(`EventArgs.Empty`).

| 이벤트 | `e` 타입 | 들어 있는 것 | 실제 사용처 |
|---|---|---|---|
| `Click` | `EventArgs` | **없음** | — |
| `ItemCheck` | `ItemCheckEventArgs` | `e.Index` · `e.NewValue` | `Stru.cs:388` · `393` |
| `OnClashTestFinished` | `ClashEventArgs` | `e.ID` | `Clash.cs:1165` |
| `OnOsnapPickingItem` | `OsnapPickingItemEventArgs` | `e.Point` | `Drawing2D.cs:708` |

🔴 **이 함수는 둘 다 안 쓴다.** 실측 — `sender` 는 **코드베이스 전체에서 한 번도 안 쓰인다**
(선언 줄 말고는 0건). 핸들러 53개가 전부 받기만 한다.

**안 쓰는데 왜 받나** — `EventHandler` 가 **「`(object, EventArgs)` 를 받고 아무것도 안 돌려주는 함수」**
라는 틀을 정해뒀다. 모양이 안 맞으면 컴파일 오류. 이름은 바꿔도 되고(`s`·`args`) **타입과 순서만 고정**.

**디버거에서 볼 것** (514 에서 멈췄을 때)

| 식 | 보이는 값 |
|---|---|
| `sender` | `{Text = "도면 일괄 출력"}` |
| `sender.GetType().Name` | `Button` |
| `((System.Windows.Forms.Control)sender).Name` | `btnExtractDrawingList` |
| `e` | `{System.EventArgs}` — 비어 있음 |

> 570 줄에서 `btnExtractDrawingList.Enabled = false` 할 때 `sender.Enabled` 도 같이 `false` 가 된다
> — **같은 물건**이기 때문. 디버거로 확인 가능.
