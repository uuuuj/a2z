# 디버거로 따라가기 — 도면 일괄 출력

> `Form1.Stru.cs:514` `btnExtractDrawingList_Click` 부터 한 줄씩.
> **목표는 아키텍처가 아니라 「이 줄이 무엇을 하고 왜 있는가」에 답할 수 있는 것.**

## 이 문서를 쓰는 법

```
1. VS 에서 Form1.Stru.cs 열고 514 줄에 F9 (중단점)
2. F5 (디버그 시작) → 프로그램 뜨면 모델 열고 STRU 체크 → [도면 일괄 출력] 클릭
3. 514 에서 멈춘다. 이제 F10 (프로시저 단위 실행) 으로 한 줄씩
   · F11 은 함수 안으로 들어간다 — 지금은 안 쓴다. 밖으로 나가는 함수는 이름만 적고 넘긴다
   · F5 를 누르면 다음 중단점까지 달린다
4. 아래 표의 「조사식에 넣을 것」을 조사식(Watch) 창에 넣고 값 변화를 본다
```

**규칙 하나** — 밖으로 나가는 함수는 **지금 안 들어간다.** 「이건 무엇을 하는 함수」라고만 적고 넘어간다.
다 따라가면 끝이 없다.

## 구간 2 — `534~540` 처리할 STRU 모으기

```csharp
var checkedStrus = new List<VIZCore3D.NET.Data.Node>();
foreach (int idx in clbStruList.CheckedIndices)
{
    if (idx >= 0 && idx < _struNodeCache.Count)
        checkedStrus.Add(_struNodeCache[idx]);
}
if (checkedStrus.Count == 0) return;
```

**화면 목록은 글자만 갖고 있다.** 「3번째 줄이 체크됐다」까지만 알려주고 그게 어느 노드인지는 모른다.
`_struNodeCache` 가 **같은 순서로** 진짜 노드를 들고 있어서, 번호를 열쇠로 꺼낸다.

```
clbStruList (화면)          _struNodeCache (코드)
 0 ☑ 갑판블록 A       ←→     0  Node(Index=1024)
 1 ☐ 벽체 B           ←→     1  Node(Index=2048)
 2 ☑ 기둥 C           ←→     2  Node(Index=3072)

CheckedIndices = {0, 2}  →  checkedStrus = [Node(1024), Node(3072)]
```

**조사식에 넣을 것**

| 식 | 본다 |
|---|---|
| `clbStruList.CheckedIndices.Count` | 체크한 줄 수 |
| `checkedStrus.Count` | 위와 같아야 정상 |
| `checkedStrus[0].NodeName` | 첫 STRU 이름 — 화면 목록 맨 위 체크한 것과 같은지 |

| 이름 | 무엇 |
|---|---|
| `var` | 타입을 안 적어도 **컴파일러가 오른쪽을 보고 채운다.** 여기선 `List<Node>` |

## 구간 5 — `579~625` 화면 깨끗이 하기

**가장 긴 블록인데 하는 일은 단순하다 — 이전 작업의 잔재를 전부 지운다.**

```csharp
vizcore3d.BeginUpdate();            // 화면 그리기 잠깐 멈춤
try {
    (1) 전체 모델 표시              GetPartialNode(false,false,true) → Show(…, true)
    (2) 2D 캔버스 잔재 제거          DeleteAllObjectBy2DView / DeleteAllNonObjectBy2DView
    (3) 3D 풍선·치수·보조선 제거     Review.Note.Clear / Review.Measure.Clear / ShapeDrawing.Clear
} finally { vizcore3d.EndUpdate(); }  // 다시 그리기

(4) drawingSheetList.Clear()        시트 잔재
(5) chainDimensionList.Clear()      치수 잔재
(6) lvDrawingBOMInfo.Items.Clear()  BOM 표 잔재
(7) xraySelectedNodeIndices.Clear() 선택 잔재
(8) _lastCollectedNodeOsnapMap / _udaValueCache 캐시 비우기
```

**왜 이렇게까지 지우나** — 주석에 사연이 있다.

> 수동 작업 잔재(`drawingSheetList` 시트)가 있으면 폴링 조건(`Count > beforeSheetCount`)이
> **영원히 미충족 → 60초 타임아웃.** 자동 출력은 「처음부터 다시」라는 의도를 명확히 한다.

즉 **버그를 겪고 추가된 블록**이다. 지우지 않으면 도면이 안 나온다.

| 이름 | 무엇 |
|---|---|
| `BeginUpdate` / `EndUpdate` | **여러 번 바꿀 테니 다 끝나고 한 번에 그려라.** 없으면 깜빡이고 느리다 |
| `finally { }` | try 안에서 오류가 나도 **반드시 실행.** 안 하면 화면이 멈춘 채 굳는다 |
| `?.` 없이 `if (x != null)` | **null 검사** — 아직 안 만들어졌을 수 있는 것을 건드리기 전에 |
| `.Clear()` | 목록 비우기 |

**조사식** — 지우기 전후로 `drawingSheetList.Count` 를 보면 `N → 0` 이 된다.

## 구간 7 — `659~705` ★ 본진 — STRU 하나씩

```csharp
for (int s = 0; s < checkedStrus.Count; s++)
{
    if (cancelled || IsCancellationRequested($"STRU {s + 1} 시작 전")) { cancelled = true; break; }

    var stru = checkedStrus[s];
    ShowBusyOverlay($"STRU 처리 {s + 1}/{checkedStrus.Count}: {stru.NodeName}");
    Application.DoEvents();

    try {
        totalPdfCount += ProcessSingleStruFull(stru, saveDir);   // ★ 여기가 전부
        successCount++;
    }
    catch (OperationCanceledException ex) { cancelled = true; }
    catch (Exception ex) { failCount++; errors.Add($"{stru.NodeName}: {ex.Message}"); }

    // STRU 간 메모리 정리
    DeleteAllObjectBy2DView(); DeleteAllNonObjectBy2DView();
    GC.Collect();
    Application.DoEvents();
    Thread.Sleep(100);
}
```
