# 1교시 — 프로그램이 켜지는 순간

**여는 파일**: `A2Z/Program.cs` · `A2Z/Form1.cs` · `A2Z/Form1.BOM.cs`
**한 문장**: 생성자는 준비를 **시작만** 하고 끝나고, 진짜 준비 완료는 **벨(이벤트)** 로 나중에 온다.

---

## ① 시작점 — `Program.cs` (전체 22줄)

이 프로그램에서 **가장 먼저 실행되는 곳**. 딱 세 줄이 일한다.

```csharp
Application.EnableVisualStyles();                      // 버튼 모양을 요즘 윈도우 스타일로
Application.SetCompatibleTextRenderingDefault(false);
Application.Run(new Form1());                          // ★ 이 줄이 전부
```

`Application.Run(new Form1())` 이 하는 일:
1. `new Form1()` — **창을 하나 만든다** (→ 생성자 실행, ②로)
2. `Run(...)` — 그 창을 띄우고 **닫힐 때까지 여기서 기다린다**

프로그램이 켜져 있는 동안 `Main`은 계속 이 줄에 멈춰 있다.
나머지는 전부 **"사용자가 뭘 하면 그때 불려가는" 코드**다. WinForms 프로그램의 기본 모양.

## ② 창이 만들어지는 순간 — `Form1.cs:271` 생성자

**순서가 의미를 가진다.**

```csharp
public Form1()
{
    InitializeComponent();        // (1) 화면 만들기 — 버튼·목록 전부
    LogBuildStamp();              // (2) 로그에 빌드 시각 기록
    SetupBOMColumns();            // (3) BOM 표 컬럼 구성
    SetupAttributeColumns();      //     부재 정보 표(DataGridView) 컬럼 구성

    lvBOM.DoubleClick += LvBOM_DoubleClick;              // (4) 목록 이벤트 7개 연결
    lvClash.DoubleClick += LvClash_DoubleClick;
    ...                                                   //     (7줄)

    InitStruSearchUI();                                  // (5) 검색창을 코드로 생성

    VIZCore3D.NET.ModuleInitializer.Run();               // (6) ★ SDK 시동
    vizcore3d = new VIZCore3D.NET.VIZCore3DControl();    // (7) ★ 3D 뷰어 생성
    vizcore3d.Dock = DockStyle.Fill;                     //     부모 공간 꽉 채우기
    panelViewer.Controls.Add(vizcore3d);                 //     화면 패널에 끼워넣기

    vizcore3d.EnableWaitForm = false;                    // (8) SDK 자체 대기창 끄기 (#116)

    vizcore3d.OnInitializedVIZCore3D                     // (9) ★★ 벨① 걸기
        += Vizcore3d_OnInitializedVIZCore3D;

```

### 🔑 꼭 볼 것 — (9)번, 생성자의 마지막 줄

`vizcore3d`는 (7)에서 만들어졌지만 **아직 쓸 준비가 안 됐다.** SDK 내부 준비에 시간이 걸린다.
그래서 코드는 이렇게 쓴다:

> "준비 다 되면 `Vizcore3d_OnInitializedVIZCore3D` 를 불러줘"

그리고 **생성자는 그냥 끝난다.** `+=` 는 **부탁을 걸어두는 것**이지 지금 실행하는 게 아니다.

> ☕ **카페 진동벨.** 주문(`+=` 등록)하고 자리에 앉는다. 커피가 나오면(SDK 준비 완료) 벨이 울리고
> 그때 그 함수가 실행된다. **이게 벨①.**

### 🔍 (7) 세 줄 뜯어보기 — 화면에 3D 뷰어가 나타나는 과정

```csharp
vizcore3d = new VIZCore3D.NET.VIZCore3DControl();   // ① 만든다
vizcore3d.Dock = DockStyle.Fill;                    // ② 자리를 정한다
panelViewer.Controls.Add(vizcore3d);                // ③ 부모에 붙인다
```

**사전 지식 — 선언과 생성은 다르다.** `Form1.cs:38`에 이미 이게 있다:

```csharp
private VIZCore3D.NET.VIZCore3DControl vizcore3d;
//  🔵      🟢 타입(설계도 이름)          🩵 필드 이름
```

이건 **"이름표를 붙여둔 것"** 이지 만든 게 아니다. 이 시점에 그릇은 비어 있다(`null`).

| 줄 | 하는 일 | 빼면 |
|---|---|---|
| ① `new ...()` | **물건을 진짜로 만들어** 38줄의 그릇에 담는다 | `null` → 쓰는 순간 프로그램이 죽음 |
| ② `.Dock = Fill` | **부모 안에서 어떻게 자리 잡을지** 정한다 | 창을 키워도 뷰어가 안 커짐 |
| ③ `Controls.Add(...)` | **부모 상자에 붙인다** | 만들어졌지만 **화면에 안 보임** |

**만들고 → 자리 정하고 → 붙인다.** WinForms에서 코드로 부품을 추가하는 표준 순서다.

**왜 코드로 만드나** — 다른 버튼·목록은 Designer(화면 편집기)에서 끌어다 놓았는데 이것만 코드다.
SDK 컨트롤은 라이선스·초기화 때문에 **디자이너에 올려두면 문제가 생기는 경우가 많아** 실행 시점에 만든다.
같은 이유로 `InitStruSearchUI()`도 검색창을 코드로 만든다.

**`DockStyle` 선택지**: `None`(좌표 그대로) · `Top`/`Bottom`(가로로 붙음) · `Left`/`Right`(세로로 붙음) · **`Fill`(남은 공간 전부)**

**화면은 러시아 인형 구조다** — 상자 안에 상자:

```
Form1 (창)
 └ splitContainer1 (좌우 분할)
    └ Panel2 (오른쪽 칸)
       └ panelViewer (Dock=Fill, 1138×1000)   ← Designer가 만듦
          └ vizcore3d (Dock=Fill)              ← 이 3줄이 만들어 넣음
```

`Fill`이 **사슬로 이어진다.** 창을 키우면 splitContainer1 → Panel2 → panelViewer → vizcore3d 순으로
전부 따라 커진다. 각자 "부모를 꽉 채워라"만 알면 전체가 알아서 맞춰진다.

#### ⚠ 순서에 함정이 있다 — 코드에 기록돼 있음

`InitStruSearchUI()` 주석:

```csharp
// 자식보다 패널을 먼저 붙여 Dock 폭을 확정한다.
// 기본 폭(200)인 상태에서 Anchor 자식을 넣으면 이후 폭 확장분(≈+237)이 그대로 오른쪽으로 밀려
// Right Anchor 버튼이 패널 밖으로 나가 화면에 보이지 않는다.
```

**부모에 먼저 붙여야 부모의 진짜 크기를 알 수 있다.** 버튼이 화면 밖으로 나가는 사고를 겪고 남긴 기록이다.
이런 **"순서가 중요한 지점"** 이 곳곳에 있다 — 아래 (5) `GenerateEdgeData`(파일 열기 前에 켜야 함)도 같은 종류.

부수 확인 — (8)의 긴 주석은 실기에서 나온 사고 기록이다.
SDK 대기창과 자체 오버레이가 **둘 다 떠서** 화면에 `Please Wait / Processing...` 글자만 남았다 (2026-08-04 사내 실기).

## ③ 벨①이 울리면 — `Form1.BOM.cs:150`

```csharp
private void Vizcore3d_OnInitializedVIZCore3D(object sender, EventArgs e)
{
    if (!InitializeLicense()) return;                       // ★ (1) 라이선스

    vizcore3d.ToolbarDrawing2D.Visible = true;              //   (2) 화면 설정
    vizcore3d.ModelTreeVisible = true;
    vizcore3d.View.MarineAxis.Visible = true;               //       좌하단 축 표시기 (T-050)

    vizcore3d.Clash.OnClashTestFinishedEvent                // ★★ (3) 벨② 걸기
        += Clash_OnClashTestFinishedEvent;
    vizcore3d.Object3D.OnObject3DSelected                   //   (4) 3D 선택 이벤트
        += Object3D_OnObject3DSelected;

    vizcore3d.Model.GenerateEdgeData = true;                //   (5) 모서리 데이터 켜기
    vizcore3d.Model.LoadEdgeData = true;                    //       — 파일 열기 前에 해야 함
    vizcore3d.Object3D.GenerateEdgeData();
```

### 🔴 (1)번 줄이 알려진 결함이다

```csharp
if (!InitializeLicense()) return;
```

라이선스 인증이 실패하면 **여기서 빠져나가고 (2)~(5)가 전부 안 돈다.**
결과는 **"창은 떴는데 아무것도 안 되는 상태"**. 오류 창은 한 번 뜨고 사라지며 재시도 수단이 없다.
→ 조사 중 나온 **결함 7건 중 하나**. 코드에서 눈으로 확인된다.

### 🔑 (3)번 줄이 벨②다

여기서 또 부탁을 건다 — "간섭검사가 끝나면 `Clash_OnClashTestFinishedEvent` 를 불러줘".
**치수 추출 전체가 이 벨에 매달려 있다.** → [4교시](./4교시%20—%20치수%20추출%20사슬.md)

### (5)번 주석 — 순서 제약

`// 파일 열기 전 설정 필요`. 모서리 데이터는 **파일을 열기 전에** 켜야 한다.
순서가 틀리면 도면에 모서리가 안 나온다. 이런 **"순서가 중요한 SDK 설정"** 이 여러 군데 있고,
리팩토링 때 함부로 순서를 못 바꾸는 이유다.

## 정리

| | |
|---|---|
| 진입점 | `Program.cs` `Main()` → `Application.Run(new Form1())` |
| 창 생성 | `Form1.cs:271` 생성자 — 화면 → 이벤트 → SDK → **마지막에 벨 등록** |
| 벨① | `OnInitializedVIZCore3D` → `Form1.BOM.cs:150` — 라이선스 · 화면 설정 · **벨② 등록** |
| 결함 | 라이선스 실패 시 `return` → "켜졌지만 안 되는" 상태 |

**이 패턴이 프로그램 전체에 깔려 있다.** 함수 하나를 읽고 "여기서 끝나네" 하면 틀린다 —
항상 **"어떤 벨을 걸어놨나"** 를 같이 봐야 한다.
