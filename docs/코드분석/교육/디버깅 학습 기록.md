### 이벤트 핸들러의 매개변수 — `object sender` · `EventArgs e`

```csharp
private void btnExtractDrawingList_Click(object sender, EventArgs e)
//                                       ──┬──  ──┬──  ────┬───  ┬
//                                        타입    이름     타입   이름
```

- **`sender`** = 눌린 **버튼 객체 그 자체**. `object` 는 타입 이름일 뿐
- **`e`** = 그 이벤트에 딸려 온 정보
- 버튼 객체는 **창이 만들어질 때 이미 생성**돼 있다 (`Form1.Designer.cs:479~483`).
  누르는 순간 새로 만들어지는 게 아니라 **있던 객체를 넘겨준다**
- 객체는 복사되지 않고 **자리(참조)만 넘어간다** → `sender.Enabled` 를 바꾸면 원본 버튼이 바뀐다

**"보낸다"의 뜻** — 우편이 아니라 **함수를 부르며 인자로 건네는 것**.
우리가 `ProcessSingleStruFull(stru, saveDir)` 하는 것과 같고, **부르는 주체가 WinForms 일 뿐**이다.

**왜 `sender` 를 주나** — 「눌렸다」는 함수가 불린 사실 자체로 전달된다.
`sender` 는 **「어느 것이 눌렸나」**에 답하는 값이다. 버튼 여러 개를 한 함수에 걸었을 때 필요하다.

🔴 **실측 — 이 코드베이스는 전부 1:1 배선이다.** 한 핸들러가 여러 컨트롤에 걸린 경우 0건.
그래서 **`sender` 는 선언 줄 말고 사용 0건.** 핸들러 53개가 전부 받기만 한다.

### `Click` 의 `e` 는 빈 객체가 아니다

디버거로 보면 `e` 에 `X=92 Y=14 Button=Left` 가 들어 있다.
선언은 `EventArgs` 인데 **실제로 들어온 물건은 `MouseEventArgs`** — 자식 타입이라 그 자리에 들어간다.

- 좌표 기준은 화면이 아니라 **그 버튼의 왼쪽 위(0,0)**.
  `btnExtractDrawingList` 는 `120 × 28` (`Designer.cs:481`) 이라 `(92,14)` 는 버튼 안 오른쪽 3/4 지점
- **키보드로 누르면 다르다** — Tab 으로 포커스 후 Space/Enter 면 `e` 는 정보 없는 `EventArgs`
- 그래서 `(MouseEventArgs)e` 로 캐스팅하면 **키보드 입력에서 예외**가 난다.
  쓰려면 `e as MouseEventArgs` + null 검사

| 이벤트 | `e` 타입 | 들어 있는 것 | 이 코드의 사용처 |
|---|---|---|---|
| `Click` | `MouseEventArgs` 또는 `EventArgs` | 좌표·버튼 / 없음 | 안 씀 |
| `ItemCheck` | `ItemCheckEventArgs` | `e.Index` · `e.NewValue` | `Stru.cs:388` · `393` |
| `OnClashTestFinished` | `ClashEventArgs` | `e.ID` | `Clash.cs:1165` |
| `OnOsnapPickingItem` | `OsnapPickingItemEventArgs` | `e.Point` | `Drawing2D.cs:708` |

### 속성(property) 과 getter

**겉은 변수인데 실제로는 함수가 도는 것.** `MfgDrawing.cs:3634~3643` 에 필드와 속성이 나란히 있다.

```csharp
public double WeightedX;      // 필드 — 값이 든 상자
public double TotalLength;    // 필드

public MfgAxisVector Direction                       // 속성 — 읽는 순간 계산이 돈다
{
    get { return NormalizeMfgAxisVector(new MfgAxisVector(WeightedX, WeightedY, WeightedZ)); }
}
```

- **getter** = 읽을 때 도는 함수 (`get { }`) · **setter** = 넣을 때 도는 함수 (`set { }`)
- `Models.cs` 의 `{ get; set; }` 는 **자동 속성** — 컴파일러가 상자와 함수를 알아서 만든다. 사실상 필드
- **괄호가 구분점** — `()` 가 붙으면 메서드. 안 붙으면 필드 아니면 속성(선언을 봐야 구분)
- ⚠ **속성은 읽기만 해도 코드가 돈다.** 조사식에 넣으면 그 자리에서 실행된다
  (이 코드는 `Models.cs` 107개가 전부 자동 속성이고, 계산이 든 건 `MfgDrawing.cs` 3 · `DrawingSheets.cs` 5)

### 버튼 여러 개를 한 함수로 묶는 방법 — 이 코드는 이미 하고 있다

`sender` 로 분기하는 대신 **「얇은 핸들러 + 공용 함수 + enum」** 을 쓴다.

```csharp
// Form1.DrawingSheets.cs:1261 · 1269 · 1277 — 각각 4줄짜리 껍데기
private void btnExportFabricationSheets_Click(object sender, EventArgs e)
{ ExportSheetsByKind(DrawingSheetExportKind.Fabrication); }
private void btnExportAssemblySheets_Click(object sender, EventArgs e)
{ ExportSheetsByKind(DrawingSheetExportKind.Assembly); }
private void btnExportInstallationSheets_Click(object sender, EventArgs e)
{ ExportSheetsByKind(DrawingSheetExportKind.Installation); }

private void ExportSheetsByKind(DrawingSheetExportKind exportKind)   // :1286 — 진짜 일
```

| | `sender` 로 분기 | 지금 방식 (enum 인자) |
|---|---|---|
| 구분 기준 | 버튼 이름 **문자열** | **enum** |
| 오타·이름 변경 | 조용히 깨짐 (빌드는 통과) | **컴파일 오류** |
| 코드에서 직접 호출 | 가짜 `sender` 를 만들어야 함 | 그냥 부르면 됨 |
| 디버거 | 이름을 봐야 분기를 앎 | **인자만 보면 끝** |

세 번째가 실제 값을 낸다 — **일괄 출력이 버튼을 안 거치고 같은 기능을 쓴다.**
