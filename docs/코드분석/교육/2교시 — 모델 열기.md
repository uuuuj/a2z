### (1) 파일 고르기 — L184~192 [한 줄씩]

```csharp

#### 선언부

```
private void btnOpen_Click(object sender, EventArgs e)
   ①      ②        ③        ④      ⑤        ⑥      ⑦
```

| | 무엇 | 뜻 |
|---|---|---|
| ① `private` | **접근 제한자** | 이 클래스 밖에서는 못 부른다 |
| ② `void` | **반환형** | 돌려주는 값이 없다 |
| ③ `btnOpen_Click` | **메서드 이름** | 관례일 뿐 |
| ④ `object` | **타입** | `sender`의 종류 |
| ⑤ `sender` | **파라미터 이름** | 사건을 일으킨 물건 |
| ⑥ `EventArgs` | **타입** | `e`의 종류 |
| ⑦ `e` | **파라미터 이름** | 사건에 딸린 정보 |

> ⚠ **`private void`는 "이벤트 핸들러 선언"이 아니다.** 보통 메서드와 모양이 똑같다:
> ```csharp
> private void btnOpen_Click(object sender, EventArgs e)   // 이벤트 핸들러
> private void BuildBodyToPartNameMap()                    // 그냥 메서드
> ```
> 이벤트 핸들러로 만드는 건 오직 `Designer.cs`의 `+=` 한 줄.
> **선언만 봐서는 구분이 안 된다 — 그래서 죽은 핸들러 8개가 티가 안 났다.**

**`object`** = C#의 **모든 타입의 조상**. 뭐든 담을 수 있어 "무엇이 일으켰는지 모르는" 자리에 쓴다.
**`EventArgs`** = 사건 정보의 **빈 껍데기**. 마우스면 `MouseEventArgs`(좌표), 키면 `KeyEventArgs`가 온다.
`btnOpen_Click`은 **둘 다 안 쓴다** — 모양만 맞춰 받아둔다.

#### `OpenFileDialog dlg = new OpenFileDialog();`

**`OpenFileDialog`** = 윈도우 **표준 파일 선택창**. 우리가 만든 게 아니라 윈도우 제공이고,
메모장 「열기」에서 뜨는 그 창과 같은 물건이다.
**`dlg`** = 그냥 변수 이름 (`dialog` 줄임말). `d`라고 해도 동작한다.

📌 `vizcore3d`는 **필드**(클래스가 계속 들고 있음)지만 `dlg`는 **지역 변수** — 함수가 끝나면 사라진다.

#### `dlg.Filter = "..."` — 파일 형식 드롭다운

`|`(파이프)로 잘라 **두 개씩 짝지어** 읽는다:

| 짝 | 표시할 글자 | 실제 패턴 |
|---|---|---|
| 1 | `VIZCore3D 파일 (*.vizx;*.viz)` | `*.vizx;*.viz` |
| 2 | `VIZX 파일 (*.vizx)` | `*.vizx` |
| 3 | `VIZ 파일 (*.viz)` | `*.viz` |
| 4 | `모든 파일 (*.*)` | `*.*` |

**앞은 사람이 읽는 글자, 뒤는 컴퓨터가 쓰는 패턴.**
`*` = 아무 글자나 몇 개든 · `;` = 또는.
앞 괄호는 장식이라 `"VIZCore3D 파일|*.vizx"` 만 써도 동작한다.

#### `dlg.FilterIndex = 1;`

드롭다운에서 **처음 골라둘 항목**. ⚠ **1부터 센다** (보통 프로그래밍은 0부터) — 오래된 API의 흔적.

#### `dlg.Title = "3D 모델 파일 열기";`

창 제목 표시줄 글자. 안 정하면 윈도우 기본값("열기").

#### 🔑 `if (dlg.ShowDialog() != DialogResult.OK) return;`

**`ShowDialog()`는 창을 띄우고 거기서 멈춘다.**

```
dlg.ShowDialog() 실행 → 창이 뜬다 → ⏸ 「열기」나 「취소」를 누를 때까지 대기
                                    → 창이 닫힌다 → 결과값을 돌려주고 다음 줄로
```

이런 창을 **모달(modal)** 이라 한다 — 닫기 전엔 뒤의 프로그램 창을 못 건드린다.

`!=` = 같지 않다 · `DialogResult` = enum · `.OK` = "확인/열기를 눌렀다"
(다른 값: `Cancel` `Yes` `No` `Abort` `Retry`…)

즉 **취소하거나 X로 닫으면 아무것도 안 하고 조용히 나간다.**
`return;` 은 `void` 메서드에서 "여기서 그만".

📌 **가드 절(guard clause)** 이라 부른다 — "조건이 안 맞으면 일찍 나가기".
아래 코드 전체를 `if { }` 로 감싸지 않아도 돼서 들여쓰기가 안 깊어진다. **이 프로그램 곳곳에 있는 패턴.**

확장자 **`.vizx` / `.viz`** — VIZCore3D SDK 전용 3D 포맷.

## ③ Body → Part 매핑 — `Form1.BOM.cs:46`

### 먼저 데이터 모양

3D 모델은 나무 구조다:

```
ASSEMBLY (어셈블리 — 묶음)
   └ PART (부재 — "H형강 1번" 같은 논리 단위)   ← 이름·재질·무게가 여기
        └ BODY (형상 — 실제로 보이는 덩어리)      ← 좌표·모서리가 여기
```

**문제**: 화면에서 클릭하면 `BODY`가 잡히는데, BOM 표에 쓸 이름은 `PART`에 있다.
그래서 **"이 Body의 부모 Part가 누구냐"** 를 미리 표로 만든다.

```csharp
List<Node> partNodes = vizcore3d.Object3D.GetPartialNode(false, true, false);   // Part만
List<Node> bodyNodes = vizcore3d.Object3D.GetPartialNode(false, false, true);   // Body만
```
👉 `GetPartialNode(어셈블리?, Part?, Body?)` — **파라미터 3개가 각각 "이 종류를 가져올까"**.

### 🔑 부모를 이진 탐색으로 추정한다

```csharp
// Body 인덱스보다 작거나 같은 가장 큰 Part 인덱스가 부모
int lo = 0, hi = partIndices.Count - 1;

**SDK에 "이 Body의 부모 Part를 줘"라는 API가 없어서**,
인덱스가 나무 순서대로 매겨진다는 성질을 이용해 **이진 탐색으로 추정**한다. → SDK 우회 사례.

결과는 `bodyToPartNameMap`(이름) · `bodyToPartIndexMap`(인덱스) 두 딕셔너리.
**이 둘은 이후 거의 모든 기능이 쓴다.**

## ④ STRU 목록 채우기 — `Form1.Stru.cs:149`

```csharp
clbStruList.Items.Clear();
_struNodeCache = CollectStruList();              // ★ STRU 찾기
foreach (var stru in _struNodeCache)
{
    string display = GetStruDisplayName(stru);   // NodeName → NodePath → "(Index N)"
    clbStruList.Items.Add(display, false);       // 체크박스 목록에 추가 (false = 체크 안 됨)
    acSource.Add(display);                       // 검색 자동완성 소스 (#36)
}
lblStruTitle.Text = $"STRU 목록 ({_struNodeCache.Count}개)";
```

### 🔑 STRU는 SDK 개념이 아니다

**STRU = 도면 한 묶음의 단위.** 배 한 척 모델에 수십 개 있고 **STRU 하나 = 도면 한 묶음**이다.
그런데 SDK에는 그런 개념이 없다. 그래서 `CollectStruList()` 가 **규칙으로 찾아낸다**:

```csharp
var assemblies = vizcore3d.Object3D.FromFilter(Object3dFilter.ASSEMBLY, true);  // 어셈블리 전부
var struIndices = new HashSet<int>();
foreach (var idx in RuleByFrameworkChildParent(assemblies))    // 규칙 ①: FRMWORK의 부모
    struIndices.Add(idx);
// 향후 추가 룰 예시 (현재 미구현):
//   - RuleByUdaMarking: UDA에 "STRU"=true 마킹된 노드
//   - RuleByDepthThreshold / RuleByNameSlashPrefix ...
```

지금 규칙은 **하나뿐** — "이름이 `FRMWORK`인 어셈블리의 **부모**가 STRU다".
규칙을 더 넣을 자리까지 만들어뒀다(`HashSet` 합집합).
⚠ **모델 명명 규칙이 바뀌면 여기가 깨진다.**
