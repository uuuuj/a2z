## ③ Body → Part 매핑 — `Form1.BOM.cs:46`

### 먼저 데이터 모양

3D 모델은 나무 구조다:

```
ASSEMBLY (어셈블리 — 묶음)
   └ PART (부재 — "H형강 1번" 같은 논리 단위)   ← 이름·재질·무게가 여기
        └ BODY (형상 — 실제로 보이는 덩어리)      ← 좌표·모서리가 여기
```

**문제**: 화면에서 클릭하면 `BODY`가 잡히는데, BOM 표에 쓸 이름은 `PART`에 있다.
그래서 **"이 Body의 부모 Part가 누구냐"** 를 미리 표로 만든다.

```csharp
List<Node> partNodes = vizcore3d.Object3D.GetPartialNode(false, true, false);   // Part만
List<Node> bodyNodes = vizcore3d.Object3D.GetPartialNode(false, false, true);   // Body만
```
👉 `GetPartialNode(어셈블리?, Part?, Body?)` — **파라미터 3개가 각각 "이 종류를 가져올까"**.

### 🔑 부모를 이진 탐색으로 추정한다

```csharp
// Body 인덱스보다 작거나 같은 가장 큰 Part 인덱스가 부모
int lo = 0, hi = partIndices.Count - 1;
while (lo <= hi) { ... }
```

**SDK에 "이 Body의 부모 Part를 줘"라는 API가 없어서**,
인덱스가 나무 순서대로 매겨진다는 성질을 이용해 **이진 탐색으로 추정**한다. → SDK 우회 사례.

결과는 `bodyToPartNameMap`(이름) · `bodyToPartIndexMap`(인덱스) 두 딕셔너리.
**이 둘은 이후 거의 모든 기능이 쓴다.**

## ④ STRU 목록 채우기 — `Form1.Stru.cs:149`

```csharp
clbStruList.Items.Clear();
_struNodeCache = CollectStruList();              // ★ STRU 찾기
foreach (var stru in _struNodeCache)
{
    string display = GetStruDisplayName(stru);   // NodeName → NodePath → "(Index N)"
    clbStruList.Items.Add(display, false);       // 체크박스 목록에 추가 (false = 체크 안 됨)
    acSource.Add(display);                       // 검색 자동완성 소스 (#36)
}
lblStruTitle.Text = $"STRU 목록 ({_struNodeCache.Count}개)";
```

### 🔑 STRU는 SDK 개념이 아니다

**STRU = 도면 한 묶음의 단위.** 배 한 척 모델에 수십 개 있고 **STRU 하나 = 도면 한 묶음**이다.
그런데 SDK에는 그런 개념이 없다. 그래서 `CollectStruList()` 가 **규칙으로 찾아낸다**:

```csharp
var assemblies = vizcore3d.Object3D.FromFilter(Object3dFilter.ASSEMBLY, true);  // 어셈블리 전부
var struIndices = new HashSet<int>();
foreach (var idx in RuleByFrameworkChildParent(assemblies))    // 규칙 ①: FRMWORK의 부모
    struIndices.Add(idx);
// 향후 추가 룰 예시 (현재 미구현):
//   - RuleByUdaMarking: UDA에 "STRU"=true 마킹된 노드
//   - RuleByDepthThreshold / RuleByNameSlashPrefix ...
```

지금 규칙은 **하나뿐** — "이름이 `FRMWORK`인 어셈블리의 **부모**가 STRU다".
규칙을 더 넣을 자리까지 만들어뒀다(`HashSet` 합집합).
⚠ **모델 명명 규칙이 바뀌면 여기가 깨진다.**
