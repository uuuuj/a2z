## 4. 쓰는 틀 — 6절 고정

절 제목과 순서를 바꾸지 마세요. 나중에 5개를 합쳐야 합니다.

### 1절 · 진입점 — 언제 도는가

사용자가 **무엇을 하면** 이 파일이 도는지. 버튼 이름(화면에 보이는 한글)과 핸들러명을 같이.
버튼 말고 목록 선택·더블클릭으로 도는 것도 있으면 함께.

### 2절 · 실행 순서 — 무엇이 어떤 순서로

**번호를 매긴 단계**로. 각 단계에 `메서드명 (줄번호)`.
`Form1.md` 2절을 그대로 따라 하면 됩니다.

```
1. **`CollectBOMData()`** (L120) — 모델 전체를 훑어 부재 목록을 만든다
2. **`BuildBodyToPartNameMap()`** (L344) — Body → 부모 Part 이름 캐시
```

각 단계 끝에 **"그래서 화면에 무엇이 나타나는가"** 를 한 줄 붙이면 좋습니다.

### 3절 · 상태 — 무엇을 읽고 무엇을 쓰나

이 파일이 읽고 쓰는 필드. **`Form1.cs`에 선언된 공유 필드는 ⚠ 로 표시**하세요.
어느 게 공유 필드인지는 `자동생성/파일 구조.md` 2절에 다 있습니다.

### 4절 · 외부 호출

- **VIZCore3D SDK API** — 무엇을 왜 부르는지
- **다른 `Form1.*.cs` 메서드** — 이름 · 어느 파일 몇 줄 · 무엇을 시키는지 **한 줄만**

> 🔴 **남의 담당 파일 안으로 파고들지 마세요.** `Form1.BOM.cs`의 `치수 추출` 버튼이
> `Dimensions`·`DrawingSheets`를 부르는데, 그건 Claude Code 담당입니다.
> **"여기서 `ShowAllDimensions`(Dimensions.cs L393)를 불러 치수를 그린다"** 까지만 적고 넘어가세요.

### 5절 · 알고리즘 — 🔴 여기가 본체입니다

**자명하지 않은 계산만.** 반복문·null 체크·UI 갱신은 쓰지 마세요.

써야 하는 것:

- 수식 · 좌표계 · 단위 (mm인지 m인지, 월드축인지 화면축인지)
- 판정 기준과 **임계값** (`3.0f` 같은 상수가 왜 그 값인지, 주석에 있으면 인용)
- 정렬·필터·우선순위 규칙
- 캐시가 있으면 **무엇을 언제 비우는지**
- SDK가 못 해서 우회한 곳 (**이게 "왜 코드가 이만큼 필요한가"의 답입니다**)

### 6절 · 의심 — 확인이 필요한 것

| 🟡 | 사소하지만 기록할 것 (삼킨 예외, 하드코딩 상수) |

**추측을 단정으로 쓰지 마세요.** 확실하지 않으면 `(추정)` 또는 `(미확인)`을 붙입니다.

## 6. 미리 알아둘 것

**① 파일은 나뉘어 있지만 클래스는 하나입니다.**
12개 파일이 전부 `partial class Form1`입니다. 컴파일하면 클래스 한 개라, **어느 파일에서든 모든 필드에 접근됩니다.** 파일 경계는 접근 제어가 아닙니다.

**② `Form1.cs`가 허브입니다.**
남이 **423회** 부릅니다. `vizcore3d`(826회) · `bomList`(96회) 같은 공유 상태가 전부 거기 있고, `DiagLog`·`ShowBusyOverlay`·`BeginCancelableOperation` 같은 공용 기능도 거기 있습니다. → `파일별/Form1.md` 참고

**③ 취소는 즉시 되지 않습니다.**
무거운 작업이 UI 스레드에서 그대로 돕니다. SDK 호출 하나는 못 끊고, `ProcessCancelableUiCheckpoint` 지점에서만 멈춥니다. `Stru`의 `도면 일괄 출력`이 이 구조를 씁니다.

**④ 이벤트 배선이 세 곳에 흩어져 있습니다.**

| 어디 | 예 |
|---|---|
| `Form1.Designer.cs` | `+= new System.EventHandler(this.X)` — 자동 생성 |
| `Form1.cs` 생성자 | `lvBOM.DoubleClick += LvBOM_DoubleClick;` — 목록류 |
| **해당 파일** | `Form1.Stru.cs:236` — 코드로 만든 컨트롤에 직접 |

**⑤ 죽은 핸들러가 이미 8개 확인됐습니다.**
`Dimensions`의 `btnShowAxisX/Y/Z_Click`·`btnShowISO_Click`, `DrawingSheets`의 `btnDrawingISO/AxisX/AxisY/AxisZ_Click`. 어디에도 배선돼 있지 않습니다. **전부 축·ISO 뷰 전환이고, 살아 있는 건 `GlobalViews`의 `ApplyGlobalView` 쪽입니다.**

> 👉 **`GlobalViews`가 담당이니 확인해주세요.** 옛 구현이 두 군데 껍데기로 남은 것으로 보입니다. `ApplyGlobalView`가 그 둘을 대체한 게 맞는지, 기능 차이는 없는지.

**⑥ SDK 우회 사례가 이미 하나 나왔습니다.**
`Form1.DrawingSheets.cs:2020~2044` — 배율 지정 줌 API가 없어서 **가짜 마우스 휠 이벤트를 7번 보내 3배 확대**합니다. 담당 파일에도 이런 우회가 있는지 눈여겨보세요. **5절에 쓸 가장 값진 재료입니다.**
