# PDF 저장 구조 — 왜 장마다 따로 저장하나

> 코드 주석에서 걷어낸 이력을 여기 모은다. **주석에는 현재 동작만 적고, 왜 그렇게 됐는지는 이 문서를 본다.**
> 기준 2026-08-31.

---

## 현재 동작

**도면은 장마다 따로 저장된다.** 한 파일로 묶지 않는다.

```
「도면 일괄 출력」  →  {저장폴더}/{STRU 이름}/
                        {STRU}_제작도 1.pdf
                        {STRU}_조립도 1.pdf
                        {STRU}_조립도 2.pdf
                        {STRU}_설치도 1.pdf
                        {STRU}_가공도 1.pdf …
```

| 경로 | 저장 방식 | 코드 |
|---|---|---|
| 「도면 일괄 출력」 | 시트마다 1개 + 가공도 | `Form1.Stru.cs` `ProcessSingleStruFull` |
| 「제작도」·「조립도」·「설치도」 | 장마다 1개 | `Form1.DrawingSheets.cs` `ExportSheetsByKind` |
| 「가공도」 | 장마다 1개 | `Form1.MfgDrawing.cs` `GenerateMfgDrawingManual` |

---

## 왜 묶지 않나

### SDK 한계 두 가지

1. **`Export2PDFBy2DView`는 이어붙이지 못한다.** 지금 2D 뷰에 올라온 캔버스를 한 번에 내보낼 뿐,
   이미 저장된 PDF 뒤에 페이지를 덧붙이는 기능이 없다.
2. **묶으려면 모든 장이 동시에 살아 있어야 한다.** 저장할 때까지 전체 페이지의 2D 객체를
   뷰에 올려둬야 하는데, 조립도처럼 장수가 많으면 SDK 네이티브에서
   **"보호된 메모리" 오류로 프로세스가 즉사**한다 (2026-08-04 실기 확인).

`catch`로도 못 잡는다 — 관리 코드가 아니라 네이티브에서 죽기 때문이다.

### 그래서 "장마다 비우기"와 "PDF 한 개"는 양립하지 않는다

```
장마다 저장하고 뷰를 비운다  →  메모리 안전 ✅  ·  PDF 여러 개
전부 쌓아뒀다 한 번에 저장    →  PDF 한 개 ✅  ·  조립도에서 프로세스 즉사 🔴
```

## 이력

| 시점 | 무슨 일 |
|---|---|
| issue **#119** | *"STRU 하나 = PDF 하나"* 로 바꾸자 — 누적(`BeginPdfPageAccumulation`) 방식 도입 |
| **2026-08-04** | 조립도에서 보호된 메모리 오류로 즉사 확인 → `App.config` `Pdf.MergePages=false` 로 끔.<br>`DrawingSheets.cs`(종류별)·`MfgDrawing.cs`(가공도)에 **장별 저장 폴백 추가** |
| 〃 | 🔴 **`Stru.cs`(일괄 출력)에는 폴백을 넣지 않았다** — 이때부터 일괄 출력의 제작도·조립도·설치도가 **저장되지 않음** |
| **2026-08-31** | 코드 통독 중 발견. 폴백 추가 후, 사용자 지시로 **묶기 분기를 아예 제거** |

### 2026-08-31에 함께 잡은 것

| | |
|---|---|
| 🔴 **일반 시트 PDF 미저장** | 그리기만 하고 저장 안 함 → `CleanupBetweenPdfPages`의 `Clear2DView`로 사라짐.<br>로그엔 `"도면 N장 그림"`으로 찍혀 **성공처럼 보였다** |
| 🟠 **가공도 완료창 거짓 표시** | 비묶음인데 *"가공도 PDF 1개에 도면 N장 저장"* + 마지막 파일 경로 하나만 표시.<br>실제로는 PDF가 N개 |
| 🟠 **가공도 PDF 개수 미합산** | 주석은 *"`SuccessPdfs`를 `pdfCount`에 합산"* 인데 코드가 안 함 |
| 🟠 **죽은 매개변수** | `ProcessSingleStruFull(… , Action<int> reportPdfSaved)` — **한 번도 호출되지 않음**.<br>반환값 `pdfCount`도 버려지고 있었다 → 매개변수 제거, 반환값 직접 합산 |

> 📌 **네 건 모두 "주석은 이렇게 한다는데 코드는 안 한다"** 패턴이었다.
> 주석이 코드와 어긋나 있으면 그게 신호다.

## 묶기를 다시 켜려면

`App.config`의 `Pdf.MergePages` 를 `true` 로 바꾸면 **종류별 출력과 가공도**는 묶기 경로를 탄다.
**일괄 출력(`Stru.cs`)은 2026-08-31에 묶기 분기를 제거해 항상 장마다 저장한다.**

⚠ 켜면 조립도에서 프로세스가 즉사할 수 있다. 벤더(소프트힐스) 수정이 선행돼야 한다.

### 벤더 요청 항목

> `Export2PDFBy2DView` 가 **기존 PDF에 페이지를 이어붙일 수 있게** 해주면,
> 장마다 저장·비우기를 유지하면서도 PDF 한 개를 만들 수 있다.
> 지금은 전부 메모리에 올려두는 방법밖에 없어서 장수가 많으면 죽는다.
