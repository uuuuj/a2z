## 1. 파일 경계를 넘는 중복 — 통합에서만 보인 것

### 🔴 ① 그래프 계산이 두 벌이다

**Part→Body 역매핑 + Clash 인접 리스트 구축이 거의 자구까지 같게 두 곳에 있다.**

| 어디 | 용도 |
|---|---|
| `Form1.DrawingSheets.cs` L45~82 (`GenerateDrawingSheets` 안) | 시트 분할용 인접 리스트 |
| `Form1.Clash.cs` L1320~1350 (`IsSingleConnectedComponent` 안) | 연결성 판정용 인접 리스트 |

내 문서는 `SheetSplitter` 분리를, Codex 문서는 `ConnectivityAnalyzer` 분리를 각각 제안했다 — **같은 코드를 서로 모른 채 가리키고 있었다.** 리팩토링 방안에서 **하나의 그래프 모듈**로 합쳐야 한다. 인접 리스트를 한 번 만들어 시트 분할과 연결성 판정이 같이 쓰면 중복도 사라지고 계산도 한 번이 된다.

### 🔴 ② Osnap 수집이 세 벌이다

| 어디 | 무엇 |
|---|---|
| `Form1.BOM.cs` (`CollectAllOsnap`) | 전역 수집 + 부재별 맵 |
| `Form1.Drawing2D.cs` L211~300 (`btnCollectOsnap_Click`) | 버튼 경로 |
| `Form1.Drawing2D.cs` L490~570 (`CollectOsnapForSelectedNodes`) | 선택 부재 경로 |

셋 다 "LINE 양끝 + POINT 중심, CIRCLE·SURFACE 제외" 같은 switch다. 내 문서(Drawing2D)는 두 벌 중복만 봤고, Codex 문서(BOM)의 `OsnapCollector` 제안까지 합치면 **세 벌 → 한 모듈**이 맞다.

### 🟠 ③ UDA 읽기가 두 파일에, 쓰기가 한 파일에

| 어디 | 무엇 |
|---|---|
| `Form1.MfgDrawing.cs` (6종) | SPREF·ORIENTATION 읽기 + `_udaValueCache` |
| `Form1.DrawingSheets.cs` (5종) | PAINT CODE·DP No.·TAG No. 읽기 |
| `Form1.Attribute.cs` | UDA 추가·편집·삭제 (**쓰기**) |

내 제안(`UdaReader`)과 Codex 제안(`UdaCommandService`)은 **충돌이 아니라 읽기/쓰기 분담**이다. 단 Codex 지적대로 **`_udaValueCache` 무효화가 문제다** — 쓰기(Attribute)가 캐시를 비워줘야 읽기(가공도)가 낡은 값을 안 쓴다. 지금은 그 연결이 없다 → 리팩토링 방안에서 캐시 소유권을 `UdaReader`로 일원화하고 `UdaCommandService`가 무효화를 호출하는 구조로.

### 🟠 ④ `MeasureStyle` 세우는 블록이 세 곳

`Dimensions` L32~51 · L465~486, `MfgDrawing` L2255~2273. 값만 다르고 형태가 같다 — 스타일 프리셋 하나로.

## 2. 6절 제안 간 정합성 — 충돌 검사

**정면 충돌은 없다.** 13개 문서의 분리 제안이 서로 다른 대상을 가리키거나 상보적이다. 합쳐야 할 병합 지점만 있다.

| 병합 지점 | 관련 제안 |
|---|---|
| 그래프 모듈 | 내 `SheetSplitter` + Codex `ConnectivityAnalyzer` → **하나로** |
| Osnap | 내 `OsnapCollector`(Drawing2D) + Codex `OsnapCollector`(BOM) → 이름까지 같다. 하나로 |
| UDA | 내 `UdaReader` + Codex `UdaCommandService` → 읽기/쓰기 짝 |
| 작업 컨텍스트 | Codex가 BOM·Clash·Stru 세 문서에서 반복 지적 — *"공유 필드를 다른 partial이 직접 읽으므로 **작업 단위 컨텍스트(`DrawingJobContext`)가 먼저** 필요하다"*. 내 Form1.md 4단계(상태 묶기)와 같은 결론을 다른 각도에서 낸 것. **리팩토링 방안의 중심 개념으로 채택할 가치** |

또 하나 — Codex Stru ④의 *"시트 행 `Selected=true` 자동 적용과 직접 `ApplySheetSelection` 호출 중 하나 삭제"* 는 내 DrawingSheets 부록의 `ApplySheetSelection`/`ApplyDrawingSheetView` 겹침 의문과 같은 지대다. 시트 적용 경로가 3개(이벤트·직접 호출·뷰 적용)라는 뜻 → 방안에서 **시트 적용 단일 진입점**으로 묶는다.
