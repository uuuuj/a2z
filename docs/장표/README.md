# 설명 장표

**앱을 어떻게 쓰는지**부터 **도면의 각 요소가 왜 그 모습으로 그려지는지**까지를,
사람이 한눈에 보도록 **가로 슬라이드(HTML)** 로 정리해 모아둔 폴더.

발표용 진입점은 **[발표.html](발표.html)** — 아래 장표를 전부 합친 **단일 파일 22슬라이드**. CSS·이미지가 모두 안에 들어 있어 이 파일 하나만 옮겨도 열린다.
장표별로 따로 볼 때는 **[index.html](index.html)**.

## 두 파트

```
파트 1 · 메뉴얼   "무엇을 눌러 무엇이 나오나"
        ↓ 이렇게 나온 도면의 각 요소가
파트 2 · 룰북     "무엇을 가져와 어떤 기준으로 그리나"
```

- `docs/기술 노트/`는 **텍스트 사양**(정본 기준값) — 정밀하지만 한눈에 안 들어온다.
- 이 폴더는 그 사양을 **발표용 장표**로 시각화 — 빠르게 이해하는 용도.
- 브라우저로 바로 열거나 인쇄(가로)로 PDF를 뽑는다.

## 파일 구성

| 파일 | 역할 |
|---|---|
| `발표.html` | **발표용 통합본 22슬라이드** — 자동 생성물이므로 직접 고치지 말 것 |
| `발표.pptx` | **PPT 판 22슬라이드** — 자동 생성물. 슬라이드 1장 = 렌더 이미지 1장이라 **PPT에서 글자 수정 불가** |
| `_발표-신규슬라이드.html` | 통합본에만 있는 슬라이드(표지·목차·화면·실행 순서·도면 5종·값의 출처)의 원본 |
| `_발표-빌드.py` | 통합본 생성기 — `python _발표-빌드.py` 하면 `발표.html` 재생성 |
| `_발표-pptx빌드.py` | PPT 생성기 — `python _발표-pptx빌드.py` 하면 `발표.pptx` 재생성 |
| `index.html` | 장표별로 따로 볼 때의 목차 |
| `_deck.css` | **공통 스타일** — 색·슬라이드 뼈대·머리말·꼬리말·슬라이드 원형 3종 |
| `_템플릿.html` | 새 룰북 장표 만들 때 복사할 빈 틀 |
| `img/` | 스크린샷·PDF 캡처 |

## 통합본 고치는 법

1. 룰북·작업 순서 등 **개별 장표**는 해당 HTML을 고친다.
2. 표지·화면·도면 설명 등 **통합본 전용** 슬라이드는 `_발표-신규슬라이드.html`을 고친다.
3. 둘 중 무엇을 고쳤든 마지막에 `python _발표-빌드.py`를 돌려 `발표.html`을 다시 만든다.
4. PPT도 쓰고 있으면 이어서 `python _발표-pptx빌드.py`를 돌린다. **PPT는 HTML에서만 나온다** — PPT를 직접 고치면 다음 빌드에 사라진다.

빌드는 개별 장표의 CSS를 파일별로 격리(`.src00` 등)해 합치므로 **장표끼리 스타일이 충돌하지 않는다.**
이미지는 `{{IMG:파일명}}` 자리표시자로 적으면 빌드가 `img/`에서 읽어 base64로 박아 넣는다.

## 발표할 때

- **→ ← 방향키 · 스페이스 · 화면 클릭**으로 넘긴다 (왼쪽 22% 클릭은 뒤로).
- 표지의 목차 항목을 누르면 그 섹션으로 바로 이동한다.
- 오른쪽 아래에 현재 섹션·장 번호, 아래쪽에 진행 막대가 뜬다.
- 인쇄(가로)하면 슬라이드 1장 = 종이 1장. 조작 UI는 인쇄에서 빠진다.

## 작성 규칙

- **하나의 요소 = 하나의 HTML.** 내용이 많으면 여러 슬라이드로 나누되(세로 스크롤·스냅), **각 슬라이드는 16:9 한 장**으로 한눈에 들어오게.
- 공통 스타일은 반드시 `_deck.css`를 링크한다. **복사해 넣지 말 것** — 색·크기가 장표마다 갈라진다.
- 슬라이드 내부 치수는 `cqh`(슬라이드 높이 %)·`cqw`(폭 %)로만. 창 크기와 무관하게 비율이 유지된다.
- 수치는 **코드 선언부 기준**으로 적는다 — 사양 문서·주석은 옛 값(stale)일 수 있음.
- 슬라이드에 **기준일**을 명기한다(수치는 시점에 따라 바뀜).
- 값의 최종 출처(파일·라인)를 장표 안에 남겨, 나중에 검증 가능하게 한다.
- 제작도 / 가공도처럼 경로가 다르면 **표로 나란히** 비교한다.
