# 2026-06-15 EA 가공도 상하 2뷰 복원

## 무엇을 했는지

- `BuildMfgSceneCore`의 EA 판정을 `IsAngleFromSpref`로 다시 활성화했다.
- 엑셀 가공도 템플릿의 한 View 영역을 두 구역으로 나눠 EA 부재를 2개 뷰로 출력하도록 했다.
- 첫 번째 뷰는 기존 정면 계열 카메라와 EA 열린 방향 보정을 사용한다.
- 두 번째 뷰는 첫 번째 카메라에서 이어 돌리지 않고 독립 카메라에서 새로 만든다.
  - 최장축 X/Y: `Z_MINUS`
  - 최장축 Z: `X_MINUS` + 화면축 90도
- 첫 번째 뷰에서는 최장축 치수를 생략하고, 두 번째 뷰에서 최장축 체인 치수와 전체 치수를 생성한다.
- 과거 일부 부재를 T자형으로 만들던 `flipNewView` 추가 180도 정렬은 복원하지 않았다.
- 두 번째 뷰 캡처 실패 시 불완전한 2D 객체만 삭제하고 첫 번째 뷰는 유지한다.

## 왜 이렇게 했는지

과거 구현은 첫 번째 뷰의 PLUS/MINUS 및 180도 상태를 XOR로 계산해 두 번째 뷰에 다시 180도 회전을 적용했다. 이 추가 회전이 특정 EA 부재에서 Y 방향과 Z 방향을 다시 바꾸면서 두 뷰가 직교하는 T자형으로 출력되는 원인이었다.

이번 구현은 두 번째 뷰의 카메라를 최장축 기준으로 직접 선택해 첫 번째 뷰의 회전 이력을 전달하지 않는다.

## 이어갈 지점

관련: T-048 (EA 가공도 T자형 잘못 촬영 수정)

사내 모델에서 EA 가공도 PDF를 출력해 아래를 확인한다.

1. 두 뷰의 최장축이 모두 가로로 보이는지
2. 특정 부재가 다시 T자형으로 배치되지 않는지
3. 첫 번째 뷰에는 단면 방향 치수, 두 번째 뷰에는 길이축 체인/전체 치수가 나오는지
4. 홀과 슬롯 중심이 두 번째 뷰 길이 치수에 과도하게 포함되지 않는지
5. 5행 템플릿에서 두 뷰와 치수 문자가 인접 행을 침범하지 않는지

진단 로그는 `[EA Secondary]`, `[RenderMfgRow] ... EA primary`, `[RenderMfgRow] ... EA secondary`를 확인한다.
