# source-command-checkpoint

Use this skill when the user asks to run the migrated source command `checkpoint`.

## Command Template

# /checkpoint — 세션 체크포인트

## 너의 임무
현 대화 세션에서 한 일을 요약 파일로 저장하여, **다음 세션에서 "어디까지 했어?"에 즉시 답변 가능**하도록 한다.

## 절차

### 1. 세션 맥락 수집
- `git status --short` + `git log --oneline -n 5` 로 이번 세션의 변경·커밋 파악
- `git diff --stat` 으로 영향 파일 규모 확인
- 대화 맥락에서 **한 일, 왜, 결정 사항, 남은 일** 추출

### 2. 주제 결정
사용자가 `/checkpoint {주제}`로 주제를 지정했으면 그걸 쓰고, 아니면 대화 맥락에서 1~4단어 주제를 뽑아 kebab-case로 변환.

예:
- `/checkpoint 풍선 회피 개선` → `balloon-collision-fix`
- 사용자가 주제 미지정 + 대화는 2D 도면 버그 수정이었다면 → `drawing2d-bugfix`

### 3. 파일명 결정
- 형식: `docs/tracking-archive/tracking-원본/sessions/YYYY-MM-DD-{주제-kebab}.md`
- 이미 같은 파일이 있으면 `-2`, `-3` 등 suffix 추가
- 날짜는 시스템의 **오늘 날짜** (환경에서 주어진 날짜 사용)

### 4. 파일 작성 (템플릿)

```markdown
# YYYY-MM-DD — {주제 원문}

## 주제
이번 세션에서 다룬 핵심을 1~2문장으로.

## 배경
왜 이 작업이 필요했는지. 이전 세션에서 이어왔다면 그 참조.

## 한 일
- 구체적 변경사항 (파일별 or 기능별)
- 주요 결정 포인트 (왜 A가 아니라 B를 선택했는지)
- 커밋 해시 (있다면)

## 영향 범위
- 코드 변경: {범위 요약}
- 문서 변경: {범위 요약}
- 기타: 설정/훅/외부 의존성 등

## 이어갈 지점 ⭐ (다음 세션 복원용)
**다음에 들어왔을 때 바로 이어가려면 이 섹션만 읽으면 된다.**

- **현재 상태**: {어떤 상태에서 세션 종료했는지}
- **다음 작업 후보**:
  1. {가장 명확한 다음 액션}
  2. {대안 또는 부가 작업}
- **주의할 점**: {잊으면 안 되는 제약·전제}
- **관련 TASK/FEEDBACK/REQUEST**: T-xxx, FB-xxx, REQ-xxx

## 참고 링크
- 관련 문서: docs/기능/...
- 관련 커밋: ...
```

### 5. 저장 및 보고
- Write 도구로 파일 생성
- 사용자에게 핵심 2~3줄 보고:
  1. 저장된 파일 경로
  2. 이번 세션 한 줄 요약
  3. "이어갈 지점"의 가장 중요한 한 항목

## 주의사항

### "이어갈 지점"은 비어있으면 안 된다
작업이 완전히 끝났더라도 **"다음에 할 수 있는 후속 작업" 또는 "관련된 남은 REQUEST/FEEDBACK"** 을 적는다.

### 세션이 짧거나 탐색만 한 경우
- 단순 질문·탐색은 `/checkpoint` 호출하지 말도록 사용자에게 권유
- 호출됐으면 그래도 요약 저장은 하되 "한 일"을 간단히 적고 "이어갈 지점"에 "특별한 후속 없음 — 다음 세션은 자유롭게 시작"이라 기재

### git 커밋 안 된 변경이 있으면
파일 하단에 **⚠️ 경고 섹션** 추가:
```
## ⚠️ 미커밋 변경 있음
- {파일 목록}
- 다음 세션에서 반드시 검토 후 `/commit` 또는 revert
```

## 금지 사항
- 세션 맥락과 무관한 내용 추측해서 채우지 말 것
- 민감 정보(비밀번호/토큰) 요약 포함 금지
- 이미 작성된 sessions/ 파일 **수정·삭제 금지** (이력 보존)
